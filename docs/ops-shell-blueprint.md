# ZzabbaXterm — 운영 셸 밑그림과 개발 계획

구현을 시작할 때는 [BDD 개발 작업판](development/README.md)에서 첫 티켓과 선행 조건을 확인한다.

## 제품 방향

ZzabbaXterm은 MobaXterm에서 겪는 한글 입력·백스페이스 문제와 대화형 CLI 멈춤을 줄이고, 회사 AWS SSO로 사설 서버를 여는 운영용 데스크톱 앱이다. AI를 켜지 않아도 메인 셸의 입력 품질과 읽기 쉬운 연결 트리만으로 바꿀 가치가 있어야 한다. 아래는 구현 목표다.

UI는 Tauri 2 + HTML/CSS + xterm.js로 공유한다. 창 제어, PTY 생성·리사이즈·종료, 실행 파일과 소켓 경로는 플랫폼별 코드로 분리한다. Windows는 WebView2·ConPTY, Linux는 WebKitGTK·Unix PTY, macOS는 WKWebView·Unix PTY를 사용한다. Claude Code·Codex·Oh My Pi·OpenCode는 오른쪽 AI 패널이 아니라 가운데 메인 셸에서 각자의 대화형 UI로 실행한다.

## 화면 밑그림

Windows·Linux 기본 보기에서 사용자가 중앙을 두 탭 그룹으로 나눠 터미널을 하나씩 놓은 예다. 제목줄 핸들은 활동 표시줄과 사이드바를 합친 폭과 같다.

```text
+----+----------------+---------------------------------------------------+-----------------------+
| ZzabbaXterm [+][v]  |                                      [사이드바][AI][집중] [-][#][x] |
+----+----------------+-------------------------+-------------------------+-----------------------+
|[연]| 연결     [+][↻] | [≡ 개발 A ×] [≡ 로컬 1] [⫿]| [≡ 개발 B ×]         [⫿]| AI      [새][CLI][↻][…]|
|[파]| [검색        ] | ubuntu@dev-a:~$ _       | ubuntu@dev-b:~$         | 나: 가동 시간 확인해 줘|
|    | v 회사 개발     |                         |                         | ┌ uptime · 개발 B ────┐|
|    |   ☁ 개발 A  •   |                         |                         | │ [승인] [거절] [취소] │|
|    |   ☁ 개발 B  •   |                         |                         | └──────────────────────┘|
|    |   ⛁ 로그 버킷   |                         |                         | (@개발 B)(세션)  [모델]↑|
+----+----------------+-------------------------+-------------------------+-----------------------+
| ☁ 개발 A · SSM · 연결됨                                                                         |
+--------------------------------------------------------------------------------------------------+
```

- **제목줄**은 `핸들(앱 이름) | 새 탭(+, 종류 메뉴) | 창 이동 여백 | 사이드바·AI 패널·집중 보기 아이콘 | 최소화 | 최대화/복원 | 닫기` 순이다. 탭은 제목줄이 아니라 각 탭 그룹의 탭 줄에 있다. 새 탭 종류 메뉴는 로컬 터미널, 파일 열기, RDP·VNC 연결, S3 호환 스토리지, 새 연결 프로필을 연다. 모든 도구 단추는 아이콘이며 접근 가능한 이름과 툴팁을 같은 문구로 제공한다.
- 핸들과 빈 여백에서만 드래그로 창을 옮긴다. Windows·Linux에서는 같은 영역을 더블클릭해 최대화/복원한다. [Tauri 창 제어](https://v2.tauri.app/learn/window-customization/)로 실제 창 상태를 바꾼다. macOS는 왼쪽 핸들에 기본 신호등 자리를 두고 오른쪽 창 단추를 생략한다.
- **집중 보기**는 활동 표시줄·사이드바·AI 열을 접고 중앙 탭 그룹만 넓힌다. 창 최대화와 별개다. 다시 누르면 각 열 너비, 탭 그룹 배치와 경계, 활성 탭과 입력이 복원된다. PTY·원격 세션·진행 중인 AI 작업은 계속 동작한다.
- **왼쪽**은 MobaXterm처럼 세로 활동 표시줄과 사이드바다. 활동 표시줄의 `연결`은 연결 트리, `SFTP 파일`은 현재 포커스된 직접 SSH 탭의 SFTP 목록을 보여 준다. 같은 아이콘을 다시 누르면 사이드바를 접는다. SFTP는 포커스된 SSH를 자동으로 따라가며 선택 단계나 드롭다운이 없다.
- **연결 트리**는 프로토콜이 아닌 `그룹 → 대상`으로 정리하고, 각 행에 프로토콜 아이콘(로컬·SSH·SSM·S3·RDP·VNC)과 열린 탭 표시 점을 둔다. SSM을 거치는 SSH는 `SSM` 표지를 붙인다. 더블클릭은 기본 연결을 열고, 문맥 메뉴는 해당 대상에 설정된 접속 방식(터널, S3 버킷 열기, nano 연동, 승격, 호스트 키 등록 등)만 아이콘과 함께 보여 준다. 사이드바 머리의 `+`는 연결 마법사를 연다. 명령줄에서는 `zzabba register`로 접속 시험 없이 새 대상을 등록한다. 표시명과 실제 접속 대상은 따로 관리한다.
- **가운데 작업 영역**은 VS Code 편집기 그룹처럼 최대 4개의 탭 그룹을 좌우로 둔다. 각 그룹은 자기 탭 줄과 활성 탭을 가진다. 탭 줄의 분할 단추는 탭이 둘 이상이면 활성 탭을 오른쪽 새 그룹으로 옮기고, 하나뿐이면 같은 연결의 새 세션을 오른쪽 그룹에 연다. 탭을 다른 그룹의 탭 줄로 끌면 이동하고, 그룹 화면의 왼쪽·오른쪽 30%에 놓으면 그쪽으로 분할한다. 탭 문맥 메뉴는 분리·이웃 그룹 이동·같은 연결 새 탭·그룹 합치기·닫기를 제공한다. 마지막 탭을 옮기거나 닫은 그룹은 사라진다. 포커스는 사람의 키 입력이 갈 위치이며 한 번에 한 그룹의 활성 탭만 입력을 받는다. 편집기·원격 데스크톱·S3 탐색기도 같은 그룹에 연다.
- **S3**는 중앙 탭의 파일 관리자다. 도구줄(뒤로·앞으로·상위·새로고침·업로드·다운로드·편집), 이동 경로, 버킷·접두어 트리, 정렬 가능한 목록(이름·크기·수정 시각·스토리지 클래스), 전송 큐, 상태 줄로 구성한다. 같은 S3 대상을 다시 열면 기존 탭으로 이동한다.
- **오른쪽 열**은 기본 너비 360 CSS px의 AI 채팅 전용이다. 제목줄의 AI 아이콘으로 접고 편다. 파일 브라우저에서 **편집**을 선택하면 중앙 편집기를 연다.
- 조회 제안·한 줄 해석·승인·작업 상태·중지는 AI 채팅 안에 둔다. AI 전용 터미널이나 독립된 오른쪽 아래 영역은 없다. 채팅 입력과 새 출력은 메인 셸의 입력과 포커스에 영향을 주지 않는다.
- **상태줄**은 작업 영역 바깥, 창 전체 폭의 맨 아래 한 줄(기본 높이 24 CSS px)이다. 왼쪽은 포커스된 탭의 프로토콜 아이콘과 대상·경로·상태(`개발 A · SSM · 연결됨`), 오른쪽은 실제 AI 작업 대상과 실행 상태를 표시한다. 탭이 없으면 `연결 없음`, AI가 쉬면 `대기`다. 탭 이동·단절·AI 실행 및 중지에 따라 갱신하며, 패널 조절·스크롤·집중 보기에서도 위치를 유지한다. 도구 버튼·비밀번호·명령 원문은 표시하지 않는다.

## 연결과 인증

한 연결에서 **대상 → 전송 경로 → 서비스 인증**을 구분한다. 예: `개발 서버 / 회사 SSO로 연 SSM 터널 / xrdp용 Bitwarden 항목`. AWS 터널 승인은 xrdp 로그인이나 `sudo` 승인을 대신할 수 없다. 앱은 프로필 이름·항목 ID·키 지문 같은 참조만 저장한다.

| 작업 | 경로와 인증 | 사용자에게 보이는 결과 |
|---|---|---|
| SSM 셸 | AWS CLI + 공식 Session Manager 플러그인, IAM Identity Center 프로필의 임시 자격 증명 | 관리 노드를 골라 SSH 키 없이 셸을 연다. SSO 만료는 재로그인으로 연결하고 IAM 거부·노드 오프라인·플러그인 누락은 따로 표시한다. |
| SSH·SFTP | 직접 또는 SSH-over-SSM. SSH Agent(예: Bitwarden), 키 또는 사용자가 선택한 비밀번호. 서버 호스트 키 검증 | 같은 대상에 터미널과 파일 목록을 연다. 호스트 키가 바뀌면 중단한다. SSM 셸만 있는 대상에는 SFTP 메뉴를 숨긴다. |
| RDP·xrdp·VNC | 직접 또는 승인된 SSH/SSM 터널. RDP와 xrdp는 같은 엔진, VNC는 별도 엔진. 원격 계정·도메인 또는 VNC 인증은 해당 서비스에만 전달 | 원격 화면 탭을 연다. 터널의 로컬 주소와 원격 신원을 분리해 인증서를 검증한다. 암호화되지 않은 VNC는 인증된 터널 안에서만 제공한다. |
| 터널 | SSH 로컬·원격·동적 전달과 SSM 로컬 포트 포워딩(노드 포트, 노드에서 본 원격 호스트)을 구분. 로컬 수신의 기본값은 루프백 | 로컬·원격 끝점, 사용 중인 탭, 종료 동작을 표시한다. 포트 충돌은 알려 주고 다른 프로세스는 그대로 둔다. 마지막 소유 탭을 닫으면 앱 소유 터널을 닫는다. |
| S3·S3 호환 | AWS S3는 SSM과 같은 AWS 프로필 또는 별도 프로필. 호환 서비스는 HTTPS 엔드포인트·리전·주소 방식과 전용 키 참조를 지정 | 버킷·접두어 탐색과 업로드·다운로드를 제공한다. SFTP 파일시스템과 달리 객체 키를 그대로 보존한다. 인증이 거부되면 해당 경로에서 멈추고, 다른 서비스의 자격 증명으로 재시도하지 않는다. |

**저장된 인증 사용**은 직접 입력과 별도 동작이다. SSH 개인 키는 Agent에 서명만 요청한다. 비밀번호가 필요할 때는 사용자가 확인한 대상과 항목으로 Bitwarden CLI를 호출한다. 금고 잠김·CLI 누락·사용 취소는 각각 표시한다. 데스크톱 금고와 CLI의 잠금 상태는 별개다. 비밀은 로컬 인증 컴포넌트에만 일시 전달한다. 연결 파일·명령 인자·클립보드·콘솔 로그·AI 입력에는 남기지 않는다.

**`sudo`는 별도의 1회 요청**이다. 로컬은 명시적으로 호출한 askpass, 원격은 사용자가 설치하고 신뢰한 헬퍼와 인증된 채널이 모두 있는 경우에 사용한다. 대상·계정·명령은 로컬 UI에서 확인한다. 헬퍼가 없거나 신원이 불확실하면 사용자가 터미널에 직접 입력한다. 화면의 비밀번호 프롬프트만으로 금고를 열 수 없다. `sudo` 자체의 인증 캐시 유효 기간과 앱의 1회 승인은 별개다.

## 개발 순서와 통과 기준

1단계에서는 AWS 없이 로컬 사용감을, 2단계에서는 같은 터미널로 SSM 접속을 검증한다. 2단계가 끝나면 3·5·6단계를 병행할 수 있다. 4단계는 3단계 뒤에 진행한다.

1. **로컬 터미널과 화면.** Tauri WebView의 xterm.js가 터미널을 그리고 Rust가 PTY 수명·바이트 전달·리사이즈·자식 종료를 맡는다. IME 조합·확정, 붙여넣기, 키 입력, 터미널 제어 시퀀스, 화면 복원, PTY 행·열 전달은 CLI별 보정 대신 공통 경로에서 처리한다. 출력은 순서를 보존하고 렌더러가 처리한 만큼 읽는다. 연결 단절·출력 지연·자식 종료를 구분한다. 제목줄·상태줄과 직접 연 두 로컬 탭의 중앙 좌우 배치를 먼저 제공한다. 트리는 로컬 대상만 표시하고 오른쪽 AI 채팅은 미연결 상태로 둔다. **완료:** 두 OS에서 T1 로컬, T2 전체 8조합, T8 통과. AWS와 AI 연동은 선행 조건이 아니다.
2. **SSM 셸.** 연결 마법사에서 프로필·리전·대상을 선택하면 기존 AWS CLI와 공식 플러그인을 PTY에 연결한다. SSO 만료·권한 거부·빈 목록을 각각 표시한다. 중복 접속은 별도 탭으로 관리하며 한 탭을 닫아도 다른 세션은 유지한다. **완료:** 두 OS에서 T1의 SSM 조합과 T3 통과.
3. **SSH와 파일 편집.** OpenSSH 및 Agent를 재사용하고 SFTP에도 같은 호스트 키·인증 조건을 적용한다. 로컬 파일과 SFTP 파일은 Monaco 편집기 탭에서 연다. `nano` 대체는 사용자가 선택하는 셸 연동이며 `vim`은 그대로 둔다. 로컬 `--wait`는 탭을 닫을 때 반환한다. 원격 `nano`는 명시적으로 설치한 원격 래퍼와 파일의 인증된 읽기·쓰기 경로가 모두 있을 때만 연동한다. 저장 전 원격 파일이 바뀌면 비교·다시 읽기를 제안하면서 편집 버퍼를 유지한다. 파일 전송·편집 중 연결 단절은 실패로 표시한다. **완료:** T4 통과.
4. **원격 화면과 터널.** RDP는 Rust 쪽 IronRDP, VNC는 별도 RFB 클라이언트로 분리한다. 인증은 로컬 백엔드가 맡으며 WebView UI에 금고 비밀을 넘겨야 하는 구현은 제외한다. Windows RDP와 Linux xrdp를 따로 시험한다. **완료:** 키 입력·클립보드·리사이즈·재접속과 터널 종료의 영향을 확인하는 T5 통과.
5. **오른쪽 파일 패널의 S3.** AWS SDK에서 AWS S3와 사용자 지정 호환 엔드포인트를 분리한다. 2단계의 AWS 프로필 처리로 AWS 임시 토큰을 갱신하고, 호환 서비스 키 참조는 이 단계에서 관리한다. **완료:** 두 종류의 엔드포인트에서 T6 통과.
6. **AI 채팅과 중앙 세션 실행.** 대상과 명령을 확인하고 로컬에서 사용자 승인받는 동작을 먼저 만든 뒤, 별도 화면 없는 공용 고정 실행기와 인증 제어 채널을 연결한다. 채팅과 로컬 CLI의 제안은 같은 규칙과 승인을 거친다. **완료:** 아래 실행 규칙에 대해 T7 통과.

### AI 제안과 실행 경계

AI 작업은 사용자가 이미 열고 명시적으로 지정·확인한 중앙 터미널의 **백엔드 세션 ID와 세대**에 고정된다. 포커스를 옮겨도 승인 ID에 묶인 대상은 그대로다. 대상 재선택, 세션 종료·재연결, 승인 만료 후에는 다시 확인한다. 셸이 `vim`·비밀번호 입력·다른 작업 실행·한글 조합·줄 편집 중이거나 준비를 확인할 수 없으면 제안만 남긴다. 인증된 제어 채널과 고정 실행기만 작업을 전달한다. 일반 PTY에 모델 문자나 Enter를 주입하는 경로, 자동 SSH 접속, AI에 대한 금고·셸 권한 설정 접근은 범위에서 제외한다. 작업별로 분리할 수 없는 출력은 중앙 탭에서 본다. 자세한 계약과 시험은 [A03](development/06-ai/03-shared.md)에 둔다.

AI 원격 명령은 전송 전에 정확한 대상·명령·한국어 한 줄 해석을 표시한다. 기본 정책은 **명시 차단 → 정확히 허용한 조회 작업 → 나머지는 사용자 확인**이다. 해석할 수 없거나 복합 셸 입력이면 자동 실행 후보에서 제외한다. `Auto`의 System One은 해석·권고만 맡으며 차단이나 대상 범위를 바꿀 수 없다. 모델 설정이 없으면 규칙만 사용한다. `Bypass`는 사용자가 연 해당 세션에서 승인한 조회 작업의 반복 확인만 생략한다. 명시 차단, 대상 변경·상태 변경 확인, `sudo`·금고의 개별 승인은 그대로 적용한다. 사용자가 직접 입력한 명령과 AI가 제안한 작업을 구분한다. 중지 상태는 `중지 요청됨`, 종료 증거를 받은 `종료됨`, 단절 등으로 결과를 모르는 `종료 확인 불가`로 나눈다.

### T2 공통 절차와 기록

빈 시험 디렉터리를 사용하고, 각 CLI를 설치·인증한 상태에서 먼저 일반 OS 터미널의 정상 동작을 확인한다. 앱은 CLI를 번들하거나 자동 설치하지 않는다.

1. 각 CLI 입력창에서 `한`을 조합하는 중 Backspace를 눌러 `하`가 되는지 확인한다. 두 줄을 붙여넣고 중복이나 조기 제출 여부를 확인한다. 끝에 `도구를 사용하지 말고 1부터 100까지 한 줄씩 적어 줘.`를 붙여 전송한다.
2. 응답을 받으며 창 너비와 집중 보기를 바꾸고 다른 탭을 다녀온다. 커서·줄바꿈·입력 위치가 복원되고 출력이 계속되는지 본다. 응답이 끝나기 전에 CLI의 취소 동작을 사용한 뒤 `확인`을 보내 다시 응답을 받는다. 정상 종료 후 같은 탭의 `echo TERMINAL_OK`가 한 줄을 출력하고 입력 에코가 정상인지 확인한다.
3. 공통 부하 시험으로 Linux의 `yes`와 Windows PowerShell의 `while ($true) { Write-Output 'test' }` 출력 중 `Ctrl+C`를 눌러 프롬프트를 되찾는다. 이 시험은 각 CLI의 대화형 시험을 대신할 수 없다.
4. 결과를 아래 8칸에 따로 기록한다. OS·WebView·CLI 버전, Linux 디스플레이 세션·입력기, 실패한 단계를 적는다. CLI 미설치·인증 불가·공급자 장애는 `미실행(사유)`으로 표시해 터미널 동결과 구분한다.

## 전제와 변경 조건

- **macOS 후속 실기기 검증:** Mac이 없어도 Windows·Linux 1차 완료를 진행한다. 장비를 확보하면 같은 로컬·SSM·CLI 절차와 macOS 기본 창 버튼·한글 입력을 확인한다.
- **System One:** 공급자와 모델 식별자는 미정이다. 특정 API를 전제하지 않으며 사용자가 모델 설정을 승인한 경우에만 판단 보조를 활성화한다.
