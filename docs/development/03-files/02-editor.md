# F02 로컬·SFTP 파일을 열고 외부 변경을 보존하기

선행: F01

**사용자 결과:** `한글.txt`를 가운데 Monaco 탭에서 고친다. 그사이 서버에서 바뀐 파일은 자동으로 덮어쓰지 않고 내 편집본과 비교할 수 있다. `nano` 연동은 선택 사항이고 `vim`은 원래대로 동작한다.

**준비물:** 네이티브 Windows 11·Ubuntu 24.04 GNOME Wayland, F01에서 확인한 OpenSSH와 승인된 SFTP 시험 계정, 별도 로컬·원격 시험 폴더, UTF-8 `한글.txt`, 독립된 두 번째 SSH 세션, 원래 `nano`·`vim`이 설치된 시험 서버. 전용 시험 계정의 원격 래퍼 설치와 셸 설정 변경은 개발자가 관리자 승인을 얻은 경우에만 별도로 진행한다.

| Given (조건) | When (행동) | Then (관찰) |
|---|---|---|
| 로컬·SFTP 시험 파일을 열었다 | 내용을 고쳐 저장하고 각각 새로 연다 | 같은 대상·같은 경로에 저장한 글자가 보인다. 이름이 같은 다른 대상의 탭은 바뀌지 않는다. |
| 편집 중 두 번째 세션에서 같은 길이의 새 내용을 저장했다 | 앱에서 저장한다 | 서버에는 외부 버전이 남고, Monaco에는 내 미저장 버퍼와 비교·다시 읽기 선택이 남는다. 비교만으로 버퍼가 바뀌지 않는다. |
| 전송 중 끊기거나 최종 저장 응답을 받기 전에 연결이 끊겼다 | 오류를 확인하고 다시 연결한다 | 전송 완료·저장됨 대신 실패 또는 결과 미확인이 보인다. 미저장 버퍼를 유지하고 원격 파일을 다시 읽어 상태를 대조한다. |
| 앱이 실행 중이다 | `zzabba-edit --wait 한글.txt`를 실행하고 저장, 다른 탭 닫기, 해당 탭 닫기를 차례로 한다 | 파일은 추가 확인 없이 열린다. 저장과 다른 탭 닫기에는 계속 대기하고 요청한 편집 탭이 닫히면 호출 셸로 돌아온다. |

## 개발 순서

1. **Red — 저장 전후의 내용을 따로 시험한다.** `app/src/features/editor/editor.test.ts`에 두 대상의 동명 파일, 비교·다시 읽기 취소, 연결 끊김 후 미저장 버퍼, `--wait` 대상 외 탭 닫기를 넣는다. `app/src-tauri/src/editor/`에는 처음 읽은 바이트와 같은 크기·수정 시각이지만 내용이 다른 사례, 업로드 중단·최종 응답 누락을 넣는다. 파일의 길이만 비교하거나 연결을 성공으로 간주하면 실패다.
2. **Green — 파일 경계를 만든다.** Rust는 로컬 파일 선택 또는 F01에서 인증된 대상의 SFTP 목록 선택을 받아 파일 핸들을 발급한다. 핸들은 대상·검증한 서버 신원·원격 계정·경로에 묶는다. SFTP는 F01의 동일한 OpenSSH 실행 계획에서 데이터 파이프로 `ssh -s <대상> sftp` 서브시스템을 열고 SFTP 클라이언트로 목록·열기·읽기·쓰기·닫기 응답을 처리한다. 파일명을 원격 셸 명령에 넣지 않는다. SSM 셸만 있는 대상에는 파일 브라우저를 제공하지 않는다. `app/src/features/editor/`에서는 Monaco 모델을 핸들별로 열어 한글·줄바꿈을 보존한다. WebView에는 표시할 파일 내용과 파일 핸들만 전달하고 임의 경로 쓰기나 인증 정보는 넘기지 않는다.
3. **Green — 원본 확인과 전송 성공을 분리한다.** 파일 열기 때 Rust가 원본 바이트의 해시를 보관한다. 저장은 같은 디렉터리의 앱 전용 임시 파일에 먼저 쓰고 기존 접근 권한을 보존한다. 닫기 응답까지 성공한 뒤 원본을 다시 읽어 해시·존재 여부를 비교한다. 바뀌었으면 교체하지 말고 비교할 원격 버전을 돌려준다. 사용자가 다시 읽기를 골라도 미저장 내용 폐기를 확인한 뒤에만 모델을 바꾼다. 일치하면 로컬은 OS의 원자적 교체, 원격은 지원이 확인된 원자적 교체(예: OpenSSH `posix-rename@openssh.com`)를 사용한다. 지원되지 않는 서버는 기존 파일 삭제 후 이름 바꾸기 대신 원본을 남기고 저장 실패로 표시한다. SFTP의 해시 재확인과 rename은 하나의 조건부 쓰기가 아니다. 마지막 확인과 교체 사이의 외부 쓰기까지 막은 것으로 기록하지 않는다. 쓰기·닫기·교체 실패와 응답 유실을 구별하고, 정리할 때 이번 요청이 만든 임시 파일만 대상으로 삼는다.
4. **Green — 명시적 파일 열기만 연결한다.** 로컬 실행기 `zzabba-edit [--wait] <파일>`은 호출자 기준 절대 경로를 사용자 전용 IPC(Windows named pipe / Unix domain socket)로 전달한다. `--wait` 응답은 정확한 편집 탭의 닫기 이벤트에 묶는다. 앱 종료·IPC 단절은 오류 종료로 호출자의 대기를 풀고, 미저장 탭의 닫기 취소는 대기를 유지한다. 사용자가 선택한 셸에만 `nano` 래퍼를 둔다. 원격은 설치·신뢰된 래퍼의 요청을 인증된 세션 경로로 받고, 요청한 파일의 **동일 계정 SFTP 읽기·쓰기 경로**까지 확인한 경우에만 연다. 래퍼나 경로가 없으면 원래 `nano`를 실행한다(래퍼 내부에서는 원본의 절대 경로를 사용해 재귀 방지). `vim`·셸 출력·일반 키 입력은 가로채지 않는다.
   **원격 래퍼에서 앱으로 돌아오는 경로:** F02가 제공하고 관리자가 승인해 설치한 고정 헬퍼를 쓴다. 원격 연동을 선택할 때만, F01과 같은 호스트 키·계정으로 PTY 없는 두 번째 SSH 채널을 열어 헬퍼의 `editor-bridge` 모드를 실행한다. 헬퍼는 원격 계정 소유의 임시 디렉터리(0700)에 세션 전용 Unix 소켓(0600)을 만들고 준비 ID를 채널로 돌려준다. Rust는 이 ID와 **이 메인 탭·원격 계정·SFTP 핸들**을 함께 보관한다. 이 모드의 메인 SSH 셸은 같은 헬퍼의 셸 시작 모드를 거쳐 해당 소켓 경로를 자식 환경에 넣는다. 셸 시작 인자에는 검증된 고정 형식 세션 ID만 쓰고 사용자 파일명은 넣지 않는다.
   래퍼는 현재 경로 기준의 실제 파일 경로와 요청 ID를 그 소켓에 보내고 응답을 기다린다. `editor-bridge`는 피어 UID와 요청 크기를 확인하고 SSH 채널의 표준 입출력에 길이 구분된 요청·응답만 전달한다. Rust가 로컬 UI에 파일 열기 요청을 표시한 뒤 **그 세션에 이미 결합한 SFTP 핸들**로 연다. 다른 호스트·로컬 파일 요청으로 바꿀 수 없다. 탭을 닫으면 요청 ID로 해당 래퍼에 종료를 통지한다. 메인 세션 종료 때 보조 채널·소켓·대기를 함께 정리한다. 준비 실패는 원래 `nano`로 복귀하고, 이미 편집을 시작한 뒤 단절되면 중복 편집기를 열지 말고 오류로 반환한다. 같은 원격 계정의 두 탭에서 동명 파일을 요청해 각각 호출한 탭으로만 돌아오는지 시연한다. 이 경로는 R01의 일반 포트 포워딩을 기다리지 않는다.
5. **실기기에서 T4 파일 항목을 기록한다.** 명령은 후속 구현 시 `app/` 기준이다. `npx vitest run src/features/editor/editor.test.ts`, `cargo test --manifest-path src-tauri/Cargo.toml editor` 후 `npm run tauri dev`로 실행한다. 두 OS에서 독립된 시험 폴더의 로컬 파일과 SFTP 파일을 각각 편집·저장·다시 열어 내용을 비교한다. 두 번째 SSH 세션의 시험 디렉터리에서 `printf '외부 수정\n' > '한글.txt'`를 실행한 뒤 앱에서 저장하여 원격본/편집본이 모두 남는지 확인한다. 큰 시험 파일을 전송하다 앱 소유 전송 연결만 끊고 다른 탭과 원본을 확인한다.
6. **래퍼 수명을 시연한다.** 각 PC의 시험 디렉터리에서 `zzabba-edit --wait 한글.txt`를 실행하고 저장 → 다른 탭 닫기 → 대상 탭 닫기 순서로 반환 시점을 기록한다. SSH 셸에서 연동하지 않은 `nano 한글.txt`, `vim 한글.txt`가 원래 TUI를 여는지 확인한다. 승인된 래퍼가 있는 시험 계정에서는 같은 `nano` 호출이 정확한 파일의 편집기를 열고, 인증된 파일 경로가 사라지면 원래 프로그램으로 돌아가는지 별도로 확인한다.

**완료 증거:** OS·대상 별칭, 저장 후 다시 읽은 바이트 비교, 충돌 시 서버/버퍼 양쪽의 비밀 없는 시험 문구, 전송 단절 상태, 로컬 반환 시점과 원격 래퍼 유무별 실제 열린 프로그램을 남긴다. 이 증거는 T4의 파일 항목이다. [F03](03-elevation.md)의 인증 취소·sudo 증거와 합친 뒤 T4 전체를 판정한다. 준비할 수 없었던 조합은 `미실행(사유)`으로 남긴다.

## 로컬 편집 검증

1. 새 임시 폴더의 `left`와 `right`에 내용이 다른 UTF-8 `same.txt`를 만든다. 로컬 앱의 **파일 열기**에서 선택을 취소하고 탭 수가 그대로인지 확인한다. 두 파일을 각각 선택해 가운데 열에 표시하고, 왼쪽 파일을 저장한 뒤 두 파일의 디스크 내용을 각각 확인한다.
2. 한 탭을 편집하고 그 파일을 앱 밖에서 바꾼다. **원본과 비교** 후 **저장**이 충돌로 끝나고 외부 파일과 편집 버퍼가 모두 남는지 확인한다. **다시 읽기**를 취소하면 같은 상태를 유지해야 한다. 다시 승인한 뒤에는 디스크 내용이 편집기에 나타나고 다음 저장이 성공해야 한다.
3. 미저장 편집 탭의 닫기를 취소하고 다시 눌러 폐기한다. 다른 동명 탭, 터미널 세션과 좌우 열이 그대로 남는지 확인한다. 저장 응답 지연과 탭 활성 세대 전환은 편집기 Vitest에서 재현한다.
4. 임시 파일의 바이트를 `a\r\nb\nc`로 만들고 마지막 `c`만 `C`로 바꿔 저장한다. 디스크 바이트는 `a\r\nb\nC`여야 한다. 미저장 내용을 추가하고 비교에 성공한 뒤 디스크에서 시험 파일을 삭제해 다시 비교한다. 이전 원본 비교는 닫히고 실패 상태와 미저장 내용이 남아야 한다.
5. CRLF와 LF를 번갈아 쓴 1,000줄을 Monaco의 전체 바꾸기로 편집한다. Monaco가 여러 변경을 하나의 범위로 합쳐 원래 줄바꿈의 위치를 확인할 수 없으면 저장 오류와 편집본이 남고 디스크 원본은 그대로여야 한다. 해당 편집을 실행 취소하고 범위가 명확한 변경을 저장하면 원래 줄바꿈을 유지해야 한다.
6. 로컬 터미널과 이미 열린 편집 탭 사이를 오간다. 선택한 탭의 입력에 포커스가 가고 편집 탭의 미저장 버퍼가 그대로 남아야 한다.
7. SSM 탭의 종료 확인과 로컬 편집 탭의 저장 응답을 지연시킨다. 저장 중에는 편집 탭 닫기가 대기하고, SSM 종료가 먼저 확인되어도 편집 탭이 선택된 상태로 남아야 한다. 저장 중 추가한 편집은 응답 뒤에도 미저장 상태여야 한다. 폐기 취소 후 다시 닫기를 승인하면 로컬 터미널에 포커스가 돌아와야 한다. `Workspace.test.tsx`는 이 순서와 파일 핸들·PTY 세션 ID를 함께 확인한다.

로컬 파일 핸들은 네이티브 파일 선택 또는 사용자 전용 IPC에서 받은 명시적 `zzabba-edit` 요청으로 발급되며, 열릴 때의 WebView 문서에 속한다. React 탭의 파일 연결과 활성 세대는 UI 오동작을 막는 장치다. 같은 문서의 탭은 보안 주체를 공유한다. 비교는 Rust 저장 기준을 읽기 전 상태로 유지하고, 확인한 다시 읽기만 Rust 기준을 새로 설정한다.

`zzabba-edit`는 실제 로컬 UTF-8 파일을 8 MiB까지 연다. Windows에서 원격 공유 경로와 연결된 디렉터리 경유 경로는 제외하며, CLI에서 열려면 앱을 일반 권한으로 실행한다.

## 파일 브라우저 배치와 세션 검증

상태: `미실행`. 중앙 SSH 탭 두 개를 좌우에 놓고 왼쪽 트리에 등록한 S3 대상을 사용한다. SFTP와 S3는 오른쪽 `AI 채팅 / 파일` 중 **파일** 한 자리를 공유한다.

| Given (조건) | When (행동) | Then (관찰) |
|---|---|---|
| 중앙 SSH 탭에 터미널이 열려 있고 AI 채팅에 미전송 초안이 있다 | 오른쪽 **파일** 탭에서 폴더를 열고 **AI 채팅**을 거쳐 **파일**로 돌아온다 | 채팅 초안과 파일 경로가 유지되고, 같은 SSH 세션과 해당 탭의 SFTP 보조 연결이 이어진다. 중앙 터미널은 그대로 보인다. |
| **파일**이 활성 SSH A의 SFTP를 따라가고 있다 | 중앙 터미널 B를 활성화한다 | 오른쪽 **파일**은 B의 SFTP를 표시한다. A의 SFTP 연결과 경로는 유지된다. |
| **파일**이 SSH를 따라가고 있다 | 왼쪽 트리의 등록된 S3 대상을 연다 | 오른쪽 **파일**에 S3가 고정된다. 기존 SSH·SFTP 연결, 중앙 터미널과 좌우 분할이 유지되고 중앙에 S3·SFTP 브라우저 탭이 추가되지 않는다. |
| S3를 고정한 뒤 접두어를 열었다 | 다른 SSH를 활성화하고 **AI 채팅**을 거쳐 **파일**로 돌아온다. **활성 SSH 따라가기**를 누른 뒤 트리에서 같은 S3를 다시 선택한다 | 고정 중에는 활성 SSH나 오른쪽 탭을 바꿔도 같은 S3 접두어가 보인다. 따라가기로 복귀하면 현재 SSH의 SFTP가 보이고, 같은 S3를 다시 선택하면 새 연결 없이 기존 세션과 접두어를 표시한다. |
| 파일 브라우저에서 폴더를 열고 파일을 선택했다 | 목록 보기와 아이콘 보기를 오간 뒤 선택한 파일을 우클릭하고 **편집**을 고른다 | 두 보기에서 현재 경로와 선택한 파일이 같다. 우클릭은 컨텍스트 메뉴만 열고, **편집**을 골랐을 때 추가 확인 없이 해당 파일이 중앙 편집 탭에 열린다. |
| 표준 SFTP 연결에 파일 이력 정보가 없다 | 파일 브라우저 오른쪽 위의 이력 표시를 확인한다 | 이력 미지원 상태가 보인다. 이전 버전이 있는 현재 파일이 0개라는 뜻의 숫자 `0`과 구별된다. |
| 두 SSH 탭의 SFTP 보조 연결과 오른쪽에 고정한 S3 세션이 열려 있다 | SSH 탭 하나를 닫고 오른쪽 파일 패널을 확인한다 | 닫힌 SSH 탭에 딸린 SFTP 보조 연결만 정리된다. 다른 SSH의 SFTP와 기존 S3 세션은 계속 사용할 수 있다. |
