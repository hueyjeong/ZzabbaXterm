# ZXT 개발 가이드

**처음이면 [F00 — 내 PC에서 앱 열기](00-start/01-bootstrap.md)부터 시작한다.** 한 사람이 개발할 때는 아래 표를 위에서 아래로 따라간다. 첫 번째 목표는 원격 서버도 AI 계정도 없이 가운데 셸에서 `echo TERMINAL_OK`가 동작하는 것이다. 그다음 한글 입력과 네 CLI가 일반 터미널에서처럼 동작하는지 확인한다. 여기에는 실행 계획만 있다. 아래 경로와 명령은 각 티켓에서 구현할 때 사용한다.

[제품 청사진](../ops-shell-blueprint.md)은 화면과 T1–T8의 인수 기준, [구현 규칙](working-agreement.md)은 기술 선택·프로세스 경계·BDD 작업법의 기준이다. 아래 표는 완료 조건이다. 실행 증거는 해당 티켓과 PR에 OS·빌드·시나리오별로 기록한다.

## 작업판

| 티켓 | 선행 | 끝나면 직접 해 볼 수 있는 일 |
|---|---|---|
| [F00 · 첫 실행](00-start/01-bootstrap.md) | 없음 | 네이티브 창을 열고 닫은 뒤 잠금 파일로 같은 환경을 다시 구축한다. |
| [L01 · 내 셸](01-local/01-shell.md) | F00 | 명령을 입력하고 실제 셸의 출력을 본다. |
| [L02 · 작업 화면](01-local/02-workspace.md) | L01 | 두 로컬 터미널을 직접 좌우에 놓고 집중 보기를 왕복해도 같은 세션과 입력을 유지한다. |
| [L03 · 한글과 CLI](01-local/03-input.md) | L02 | 조합 중 글자를 지우고 대화형 CLI를 취소한 뒤 다시 입력한다. |
| [C01 · 연결 등록](02-connections/01-profiles.md) | L03 | 그룹에서 저장한 대상을 다시 열고 취소한 초안은 버린다. |
| [C02 · 회사 SSM](02-connections/02-ssm.md) | C01 | SSO 프로필로 선택한 노드에서 `whoami`를 실행한다. |
| [F01 · SSH 로그인](03-files/01-ssh.md) | C02 | 검증한 호스트에 Agent 또는 연결별 인증으로 접속한다. |
| [F02 · 파일 편집](03-files/02-editor.md) | F01 | 선택한 파일을 추가 확인 없이 열고 저장 충돌 때 원본과 편집본을 보존한다. |
| [F03 · 권한 상승 확인](03-files/03-elevation.md) | F01 | 같은 호스트에서도 `sudo` 요청은 별도로 확인한다. |
| [R01 · 터널](04-remote/01-tunnels.md) | F02, F03 | 어느 탭이 어느 끝점을 쓰는지 확인하고 마지막 소유 탭에서만 터널을 닫는다. |
| [R02 · 원격 데스크톱](04-remote/02-rdp.md) | R01 | Windows RDP와 Linux xrdp 화면에서 입력한다. |
| [R03 · VNC](04-remote/03-vnc.md) | R01 | 인증된 경로에서 VNC 화면을 열고 끊긴 탭만 다시 연결한다. |
| [S01 · AWS S3](05-storage/01-s3.md) | C02 | 같은 AWS 프로필로 시험 객체를 올리고 원본 그대로 내려받는다. |
| [S02 · S3 호환](05-storage/02-compatible.md) | S01 | 서비스별 엔드포인트와 키 참조로 같은 작업을 반복한다. |
| [A01 · 채팅과 제안](06-ai/01-proposals.md) | C02 | 채팅이나 로컬 CLI로 제안을 만들고 어디서 무엇을 할지 확인한다. |
| [A02 · 공용 실행 기반](06-ai/02-dedicated.md) | A01 | 별도 화면 없이 고정 조회를 인증 채널로 전달하고 작업별 중지·종료 증거를 구분한다. |
| [A03 · 지정한 중앙 세션에서 실행](06-ai/03-shared.md) | A02 | AI 채팅에서 검토하고 직접 지정·확인한 세션에서만 한 번 실행한다. `vim`이나 입력 중에는 제안만 본다. |
| [D01 · 설치본 인수](07-delivery/01-acceptance.md) | L03, C02, R02, R03, S02, A03 | Windows·Linux 설치본에서 시험 기록을 모아 인계한다. |
| [M01 · Mac 실기기](07-delivery/02-macos.md) | D01 + Mac 확보 | 같은 기능을 macOS에서 시연하고 기본 창 버튼과 한글 입력을 따로 판정한다. |

**함께 개발할 때:** C02를 마치면 SSH·파일(F01), 스토리지(S01), AI 제안(A01)을 병행할 수 있다. S3 호환 키 참조는 S02가, AI의 로컬 확인은 A01이 맡는다. AWS 접속이 막혀도 로컬 셸 합격 여부는 판정할 수 있다. Mac 부재는 D01의 차단 사유가 아니다.

## 통과 지점

| 시점 | 인수 항목 | 다음 단계로 넘길 증거 |
|---|---|---|
| L03: AI 없이 터미널 교체 | T1 로컬, T2, T8 | 물리 IME 두 환경, OS × CLI 8칸, 실제 창 전환과 세션 보존 |
| C02: 첫 회사 서버 | T1 SSM, T3 | 비운영 노드의 실제 셸 응답, 연결 실패 구분, 다른 탭의 생존 |
| F02 + F03: 파일·인증 | T4 | 저장 충돌 때 버퍼 보존, `--wait` 반환, 인증 취소·승격 수동 확인 |
| R01 + R02 + R03: 화면 접속 | T5 | 세 서비스의 실제 화면·입력, 터널 충돌·종료 영향 |
| S01 + S02: 객체 왕복 | T6 | 두 엔드포인트 각각의 원본과 다운로드 바이트 일치 |
| A01 + A02 + A03: AI 보조 | T7 | 기본/Auto/Bypass별 세션 ID·세대·승인 ID, 포커스 독립, 만료·다른 세션·입력 중 거부, 중지·단절 증거 |

티켓을 닫기 전 마지막 단계는 [BDD 증거 기록](working-agreement.md#티켓을-닫는-법)이다. 외부 계정·장비가 없으면 해당 칸만 `미실행(사유)`으로 남긴다. 미실행 항목이 있는 단계는 **구현됨**과 **인수 완료**를 구별해 인계한다.
