# C01 그룹 트리에서 로컬 연결을 시험하고 저장하기

선행: L03

**사용자 결과:** `회사 개발 → 작업 셸`을 선택하면 같은 이름의 다른 대상이 아니라 내가 시험한 로컬 셸이 열린다. 연결을 시험하다 취소하거나 실패해도 기존 트리는 그대로다.

**준비물:** L03의 로컬 탭·PTY, Windows 11의 PowerShell, Ubuntu 24.04 GNOME Wayland의 Bash, 쓰기 가능한 시험 디렉터리와 존재하지 않는 경로 하나. 실제 사용자 설정과 분리한 앱 설정 디렉터리를 쓴다. AWS 도구나 계정은 이 티켓의 준비물이 아니다.

| Given (조건) | When (행동) | Then (관찰) |
|---|---|---|
| 같은 표시명의 대상 두 개가 서로 다른 그룹에 있다 | 한 행을 선택해 Enter 또는 더블클릭한다 | 선택한 대상 ID의 기본 경로로 탭 하나가 열린다. 문맥 메뉴에는 그 대상에 설정된 방식만 있다. |
| 새 로컬 대상의 초안이 있다 | 유효한 시작 디렉터리로 연결을 시험한 뒤 저장하고 앱을 다시 연다 | 실제 셸이 응답했던 대상과 기본 방식이 같은 그룹에 남는다. 시험용 프로세스는 이미 종료됐다. |
| 시험에 성공한 뒤 시작 경로를 없는 디렉터리로 바꾼다 | 다시 시험하고, 실패 화면에서 취소한다 | 이전 성공은 무효다. 실제 시작 실패와 입력값이 남고, 취소 전후 저장 파일과 트리는 동일하다. |

## 개발 순서

1. **Red — 초안과 저장본을 구별한다.** `app/src/features/connections/connectionTest.test.ts`와 `sessionEditor.test.ts`에 취소·시험 실패·값 수정 후 이전 성공 결과 도착·동명 대상 선택 사례를 쓴다. `app/src-tauri/src/connections/`에 허용하지 않은 필드(예: `password`, `accessToken`)를 보낸 초안의 거부, 실패한 저장 후 이전 파일을 다시 읽는 Rust 시험을 먼저 추가한다. 직렬화할 때 비밀 필드 값을 빈 문자열로 바꾸는 구현도 실패여야 한다.
2. **Green — 데이터 경계를 만든다.** Rust가 그룹 ID·대상 ID, 표시명, 실제 대상, 접속 방식 목록과 기본 방식, 방식별 경로·서비스 인증 참조를 검증한다. 로컬 방식은 지원 셸과 시작 디렉터리만 받는다. 셸 명령 문자열이나 임의 프로그램 실행 옵션은 받지 않는다. 후속 방식에서도 AWS 프로필 이름, 키 참조·지문, 금고 항목 ID만 저장하고 비밀 값은 입력 스키마에서 제외한다. 저장 시 사용자 전용 앱 설정 경로에서 임시 파일을 완전히 쓴 뒤 기존 파일을 원자적으로 교체한다. 기록 실패는 저장 실패다.
3. **Green — 세션 편집 창을 실제 PTY에 연결한다.** `app/src/features/connections/SessionEditor.tsx`의 한 화면에서 이름·그룹·접속 방식과 방식별 필드를 편집하고 `연결 시험`·`저장`을 누른다. 로컬 인증 값은 현재 사용자다. Rust는 선택한 셸과 작업 디렉터리로 시험 전용 PTY를 열어 고정된 시험 문자열을 출력하는 셸 명령의 결과와 정상 종료를 확인한다(입력 에코를 성공으로 세지 않는다). 시간 초과·취소·창 닫기에는 해당 자식만 종료·회수한다. Rust에서 시험 결과를 초안 버전에 묶고, 현재 버전이 성공한 경우에만 시험 티켓 저장(`connection_save`)을 받는다. 시험하지 않은 초안은 입력 검증만 하는 `connection_target_save`로 저장한다. AWS 방식의 실연결 시험은 [C02](02-ssm.md)가 맡는다.
4. **Green — 저장본으로 트리를 그린다.** 그룹 아래 대상 행을 표시하고 검색 결과도 원래 그룹에 둔다. 기존 트리 폭을 쓰고 글자 15px·행 36px·행 전체 선택을 적용한다. 화살표로 이동·접기·펼치기, Enter·더블클릭으로 기본 연결, 문맥 메뉴로 설정된 다른 방식을 연다. 트리에는 영구 대상 ID, 열리는 탭에는 매번 Rust가 발급한 세션 ID를 쓴다.
5. **실기기에서 판정한다.** 아래 명령은 모두 후속 구현 시 `app/`에서 실행한다. `npx vitest run src/features/connections`와 `cargo test --manifest-path src-tauri/Cargo.toml connections`에서 1단계 사례가 실제로 실행되는지 확인한다. `npm run tauri dev`로 두 OS에서 각각 정상 경로 시험·저장·재시작과 실패 경로 시험·취소를 반복한다. 정상 행을 열어 PowerShell은 `Get-Location`, Bash는 `pwd`로 선택했던 시작 경로를 대조한다.

**완료 증거:** OS별로 정상 경로, 실패 이유, 재시작 후 열린 대상, 취소 전후 설정의 동일 여부와 시험용 자식 회수 결과를 남긴다. 저장 파일은 값 대신 필드 이름만 첨부한다. AWS 연결 결과는 이 증거에 포함하지 않는다.

## 세션 편집 창 IPC

Tauri의 로컬 `main` 창에서만 호출한다. `Run`은 `{ draftId: string, draftVersion: number, runId: string }`이다. 편집 창이 편집 식별자와 버전을 넘기면 Rust가 `runId`를 발급한다. `draftVersion`은 0 이상의 안전한 정수이며 파일 스키마 버전과 별개다.

| 명령 | 인자 | 성공 응답 |
|---|---|---|
| `connection_test_start` | `{ draftId, draftVersion, draft }` | `Run` |
| `connection_test_wait` | `{ run: Run }` | `Run & { sessionId: string }` |
| `connection_test_cancel` | `{ run: Run }` | `null` |
| `connection_save` | `{ request: { run: Run, draft } }` | `null` |
| `connections_load` | `{}` | `{ version: 2, groups: [{ revision, profile }], targets: [{ revision, profile }] }` |

`draft`는 `{ version: 2, targetRevision, target }`이다. `target.groupId`는 선택이며, 있으면 이미 저장된 그룹이어야 하고 없으면 최상위 세션이다. 시험 뒤 저장은 대상만 저장하고 그룹은 바꾸지 않는다. 새 대상의 개정은 `null`이고, 저장된 대상을 수정할 때는 목록 응답의 개정을 넘긴다. 로컬 `target`은 `{ id, groupId?, displayName, defaultMethod: "local", local: { shell, startDirectory } }`다. `shell`은 Windows의 `"powerShell"` 또는 Ubuntu의 `"bash"`이며, `startDirectory`는 절대 경로이거나 빈 문자열이다. 빈 문자열이면 열기와 연결 시험 때 사용자 홈 디렉터리에서 시작한다. 로컬 인증은 현재 사용자이므로 인증 필드는 없다.
Windows의 시험과 저장 대상 열기는 일반 드라이브 절대 경로를 받는다. 확장 경로, 장치 경로, UNC 경로는 경로 오류로 반환한다.

1. `start`에 현재 초안을 넘긴 뒤 반환된 `Run`을 `wait`에 그대로 전달한다. PTY 생성부터 시험 표식·정상 종료·회수까지 합쳐 8초 안에 끝나야 성공한다. 기한이 지나면 오류를 반환하고 아직 남아 있는 해당 시험은 백그라운드에서 회수한다.
2. 편집하거나 편집 창을 닫으면 이전 `Run`을 취소한다. `null`은 저장 자격 폐기와 중지 요청의 응답이다. 아직 진행 중인 OS 정리는 소유 창의 실행 목록에 남겨 완료 시 수거한다. `start` 응답이 늦으면 도착한 `Run`을 취소하며, 재시험·문서 이동·창 닫기도 해당 실행만 취소한다.
3. 사용자가 시험에 성공한 초안에서 저장을 누를 때만 `connection_save`를 호출한다. SSM과 S3는 이 경로로 확인한 계정 ID를 함께 저장한다. 시험하지 않았거나 시험 뒤 입력을 바꾼 초안, 저장 암호 SSH, RDP, VNC는 `connection_target_save`로 저장한다. Rust는 파일 잠금을 얻은 뒤와 최종 교체 직전에 창·문서·실행·초안이 여전히 일치하는지 확인한다. 최종 승인 전에 문서가 사라지면 기존 파일은 그대로다. 최종 승인 뒤에는 교체를 마치며, 성공한 실행의 저장 자격은 소진된다. 저장 뒤 `connections_load`로 새 개정과 목록을 받는다.

## 저장 스키마 v2

`connections.json`의 `version`은 2다.

- 그룹: `{ id, displayName, parentId? }`. `parentId`가 없으면 최상위 그룹이다. 부모는 존재해야 하고, 순환은 거부하며, 최상위를 1단계로 최대 8단계다.
- 대상: `groupId`는 선택이다. 없으면 그룹 없는 최상위 세션이다.
- v1 파일은 메모리에서 v2로 읽는다. v1 그룹은 모두 최상위 그룹이다. 처음 v2로 쓰기 직전에 같은 잠금 아래에서 원본을 `connections.v1.json`으로 한 번 복사한다. 임시 파일을 다 쓴 뒤 덮어쓰지 않는 링크로 확정한다. v1으로 읽히는 백업이 이미 있으면 그 뒤에 다시 나타난 v1 파일은 백업하지 않는다. 비었거나 v1이 아닌 백업은 다시 만든다. v1 파일에 `parentId`가 있거나 `groupId`가 빠진 대상이 있으면 형식 오류다.
- 원격 화면의 SSH 경로(`route.kind: "ssh"`)가 가리키는 대상은 Agent 또는 키 파일 인증의 직접 SSH 대상이어야 한다. 어떤 쓰기도 새로 이 조건을 깨면 저장하지 않는다.

## 그룹과 세션 편집 IPC

로컬 `main` 창에서만 호출한다. 모든 쓰기는 파일 잠금 아래에서 개정을 비교하고 원자적으로 교체한다.

| 명령 | 인자 | 성공 응답 |
|---|---|---|
| `connection_group_save` | `{ draft: { version: 2, revision, group } }` | `{ revision }` |
| `connection_group_delete` | `{ id, revision, expected: [{ kind: "group" \| "target", id, revision }] }` | `null` |
| `connection_target_delete` | `{ id, revision }` | `null` |
| `connection_target_save` | `{ draft: { version: 2, targetRevision, target } }` | `{ revision }` |

- 새 항목의 개정은 `null`이다. 그룹 저장은 추가, 이름 바꾸기, 이동(`parentId` 변경)을 맡는다.
- 그룹 삭제는 하위 그룹과 그 안의 세션까지 지운다. `expected`는 루트를 뺀 하위 그룹과 세션의 집합이며, 저장본과 정확히 같아야 지운다.
- `connection_target_save`는 연결 시험 없이 입력만 검증한다. SSM과 S3는 방식, 프로필, 리전이 저장본과 같고 저장된 계정 ID가 있으면 유지하고, 아니면 로컬 SSO 설정의 `sso_account_id`를 기록한다. 설정이 없으면 비워 두며, 스토리지를 열 때 연결 재시험이 필요하다.
- `tested_account_id`는 연결 시험(STS 확인값) 또는 시험 없는 저장 시점의 SSO 설정에서 확정한 계정이다.

오류는 다음 중 하나로 거부한다.

| `kind` | 추가 필드 | 의미 |
|---|---|---|
| `invalid` | `field` (`displayName`, `parentId`, `groupId`, `ssh.host`, `ssh.port`, `desktop.route` 등) | 입력 검증 실패 |
| `conflict` | | 개정이나 하위 항목 집합이 저장본과 다름 |
| `referenced` | `targets` | 원격 화면 세션이 SSH 경로로 사용 중 |
| `failed` | `message` | 그 밖의 읽기·쓰기 실패 |

## 연결 트리와 메뉴

`app/src/features/workspace/LocalTree.tsx`가 저장본을 트리로 그린다.

- 순서는 합성 "로컬" 그룹("내 PC"), 최상위 그룹, 그룹 없는 최상위 세션이다. 그룹은 `parentId`로 중첩하고, 그룹 안에서는 하위 그룹을 세션보다 먼저 둔다. 없는 부모를 가리키는 그룹은 최상위에 둔다.
- 행은 `role="treeitem"`과 `aria-level`(최상위 1)을 갖고, 하위는 `role="group"` 목록에 둔다. 들여쓰기는 같은 값의 `--tree-level`로 계산한다.
- 검색하면 이름이 일치하는 항목과 그 조상 그룹만 남긴다. 이름이 일치한 그룹은 내용을 모두 보인다. 검색 중에는 모두 펼치고, 검색을 지우면 `group:<id>` 키로 기억한 접힘 상태가 돌아온다.
- 키보드: 위·아래는 보이는 행 이동, Home·End는 처음·끝, 오른쪽은 펼치기 또는 첫 하위 행, 왼쪽은 접기 또는 상위 그룹, Enter는 세션 열기 또는 그룹 접기·펼치기, Space는 그룹 접기·펼치기, F2는 그룹 편집 또는 세션 편집, Delete는 삭제 확인, 메뉴 키와 Shift+F10은 행 메뉴다.

| 우클릭 위치 | 메뉴 |
|---|---|
| 행 밖의 빈 곳, 합성 "로컬" 그룹 | 세션 추가… · 그룹 추가… (최상위에 추가) |
| 그룹 | 세션 추가… · 그룹 추가…(최대 깊이 그룹에서는 비활성) · 편집… · 삭제 |
| "내 PC" | 로컬 · 승격 실행…(조건부) |
| 세션 | 기본 방식 열기 · S3 버킷 열기 · 터널 열기 · nano 연동으로 열기 · 승격 실행…(방식별 조건부) · (SSH) 호스트 키 확인… · 호스트 키 파일로 등록… · 편집… · 복제 · 삭제 |

- 그룹의 "세션 추가…"는 편집 창의 그룹 기본값을 그 그룹으로 연다. "그룹 추가…"는 그 그룹을 상위로 둔 그룹 창을 연다.
- 그룹 창(`app/src/features/connections/GroupDialog.tsx`)은 이름과 상위 그룹(최상위 또는 그룹, 자기 자신과 하위 제외)을 받아 `connection_group_save`로 저장한다. 상위 그룹을 바꾸면 이동이다. 고른 상위 아래에 놓인 그룹과 그 하위가 8단계를 넘으면 상위 그룹 아래에 "최대 8단계 초과"를 표시하고 저장을 막는다. Rust 오류 `invalid`(`displayName`, `parentId`)는 해당 필드 아래에, 충돌과 그 밖의 실패는 상태 줄에 표시한다.
- 그룹 삭제 확인 창은 그룹 이름과 "하위 그룹 n개, 세션 m개"만 표시한다. 창을 연 시점의 하위 그룹과 세션, 개정을 `expected`로 보내므로 그 사이 바뀌면 충돌로 거부된다.
- 그룹 저장, 그룹·세션 삭제, 세션 편집 창 저장이 충돌하면 충돌 문구를 표시하고 목록을 다시 읽는다. 입력은 그대로 두고 다음 저장이나 삭제는 새 개정과 새 하위 집합(그룹 삭제는 수도 갱신)으로 보낸다. 시험 뒤 저장의 티켓은 이전 개정에 묶여 있으므로 버리고 시험 실행을 회수한다.
- "복제"는 같은 설정, 새 ID, "이름 (복사본)"으로 새 세션 편집 창을 연다. 저장하기 전에는 아무것도 만들지 않는다. 세션 이동은 편집 창의 그룹 선택으로 한다.
- 메뉴를 닫으면 메뉴를 연 행으로 포커스를 돌린다. 트리에서 연 대화상자를 닫으면 트리의 현재 행으로 돌리고, 저장 뒤 목록을 다시 읽어 행이 사라졌으면 남은 현재 행으로 돌린다.

## CLI 연결 등록

[`zxt register`](../06-ai/01-proposals.md)는 앱 창이나 연결 시험 없이 새 연결 설정을 저장한다. 직접 SSH의 `hostKeyFingerprint`는 선택이다. 넣으면 별도로 확인한 기대 지문으로 쓴다. 호스트 키는 첫 연결에서 확인한다([SSH 호스트 키 첫 연결 확인](../03-files/01-ssh.md#ssh-호스트-키-첫-연결-확인)). 앱이 서버 키를 받아 OS 확인 창에 서버·포트·키 종류·SHA256 지문을 보여 주고, 사용자가 **신뢰**를 눌러야 고정한다. 기대 지문이 있으면 받은 키와 먼저 대조해 다르면 확인 창 없이 중단하고, 같아도 확인 창을 띄운다. 그래서 CLI가 넣은 지문만으로는 키가 고정되지 않는다. 고정한 뒤 키가 바뀌면 접속을 중단하며, 교체는 메뉴의 호스트 키 확인에서 이전·새 지문을 보여 주는 확인 창을 거친다. 행의 **호스트 키 파일로 등록**은 관리자가 준 공개 키 파일로 고정하는 대역 외 경로로 남는다.

## 원격 화면 프로필

`defaultMethod`가 `"rdp"` 또는 `"vnc"`인 대상은 원격 화면 탭을 연다. 비밀번호와 계정은 저장하지 않으며 연결할 때 서비스 인증에서 받는다.

- `rdp: { host, port, tlsOnly, route }`, `vnc: { host, port, route }`. 기본 포트는 3389와 5900이다. `tlsOnly`는 RDP의 **NLA를 지원하지 않는 서버(TLS 전용) 허용** 값이다.
- `route`는 `{ kind: "direct" }`, `{ kind: "ssh", targetId }`, `{ kind: "ssm", profile, region, instanceId }` 중 하나다.

| 경로 | 전달 목적지 | RDP `host` | VNC `host` |
|---|---|---|---|
| `direct` | `host:port` | TLS 인증 이름(DNS 이름 또는 IP) | DNS 이름 또는 IP |
| `ssh` | SSH 서버의 `127.0.0.1:port` | TLS 인증 이름(DNS 이름 또는 IP) | 빈 값 |
| `ssm` | `host`가 비면 노드 자신의 `port`, 있으면 노드에서 접속하는 `host:port` | TLS 인증 이름(DNS 이름 또는 IP) | 빈 값 |

- RDP `host`의 IP 주소는 표준 표기(`10.0.1.25`, `2001:db8::25`)만 받고 서버 인증서의 IP SAN으로 확인한다. 리졸버가 IP로 해석하는 숫자 꼬리 이름(`2852039166`, `127.1`)과 지정되지 않은 주소(`0.0.0.0`, `::`)는 거부한다.

- `ssh` 경로의 `targetId`는 Agent 또는 키 파일 인증을 쓰는 저장된 직접 SSH 대상이어야 한다. Rust가 저장할 때와 터널을 열 때 각각 확인한다. 참조 중인 SSH 대상은 지우거나 다른 인증으로 바꿀 수 없다.
- 원격 화면 프로필은 연결 시험 없이 저장한다. `connection_test_start`와 `connection_save`는 거부하고, `connection_target_save`가 스키마와 SSH 참조를 검증한다. 서버 인증서와 터널 승인은 열 때 확인한다.
