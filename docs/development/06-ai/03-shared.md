# A03 준비된 메인 셸에서 승인 작업을 한 번 실행하고 T7 판정하기
선행: A02

사용자가 특정 탭에서 `내 셸 사용`을 선택하면 승인 작업은 그 메인 셸에서만 실행된다. 오른쪽 아래에는 `메인 셸 사용 중`과 구분 가능한 작업 출력만 보인다. 셸 연동이 없는 대상에서도 사람이 쓰는 터미널은 그대로 작동한다.

**준비물:** A02의 정책·작업 실행기·인증된 제어 채널, 승인된 비운영 Linux 노드 A·B와 시험 계정, 네이티브 Windows 11 및 Ubuntu 24.04 GNOME Wayland. 구현 후 사용할 명령은 `app/` 기준이다.

## 인수 조건

- **Given** 사용자가 A 탭을 공유하고 빈 프롬프트에서 작업을 승인했다. **When** 전송 후 B로 이동한다. **Then** A 메인 셸에서만 1회 실행되며 하단 상태줄 왼쪽은 B, 오른쪽은 A의 작업 상태다. 전용 세션에서 같은 작업이 다시 실행되는 횟수는 0이다.
- **Given** 한글 조합 중, 입력 줄 편집 중, `vim`·다른 프로그램·암호 입력 중 또는 셸 상태 불명이다. **When** 제안이 도착하거나 오래된 승인이 돌아온다. **Then** 사용자 입력을 보존하고 제안만 남긴다. **Given** 작업 출력과 백그라운드 출력이 섞였다. **Then** 해당 바이트를 오른쪽으로 복사하는 대신 원래 메인 탭을 가리킨다.

## 구현 순서

1. **Red.** `src-tauri/src/ai/`에 준비 통지 뒤 첫 사람 입력, 승인과 붙여넣기 경합, 재접속, 만료된 준비 번호, 같은 승인 두 번, 탭 닫기를 테스트한다. `src/features/ai/`에서는 조합 시작부터 확정까지와 다른 탭 전환을 검사한다. 기대값은 사람의 입력 보존, 오래된 승인의 PTY 쓰기 0건, 유효한 요청만 원래 세션에 1회다.
2. **Green — 실제 준비 신호.** 공유는 사용자가 시험 계정의 Bash에 명시적으로 설치한 셸 연동부터 지원한다. 예를 들어 Bash `bind -x`로 예약한 키 시퀀스에 앱 전용 처리기를 연결한다. 처리기는 현재 셸이 자기 터미널의 포그라운드인지, `READLINE_LINE`이 비었는지, A02의 인증된 채널에 그 셸·세대의 1회 요청이 있는지 검사한다. 앱이 일반 PTY에 예약 키를 써서 처리기를 깨우면 그 순간 포그라운드가 바뀔 수 있다. 대신 공유 실행 때 **사용자가 해당 메인 탭의 빈 프롬프트에서 예약 키를 직접 누르게** 하고 처리기가 인증 채널에서 작업을 가져오게 한다. 화면의 `$`, OSC, 출력의 ‘ready’ 문구는 준비 근거로 쓰지 않는다. 공유 연동을 설치하지 않은 셸과 대화형 프로그램 안에서는 승인해도 전송 없이 제안만 남긴다.
   - **같은 탭끼리 연결하기:** `src-tauri/resources/ai/shared.bash`와 노드 측 고정 실행기를 관리자가 시험 계정에 설치한다. 공유 선택 시 A02의 제어 실행기가 노드의 사용자 전용 런타임 디렉터리(0700)에 채널별 Unix 소켓(0600)을 열고 일회용 연결 코드를 Rust에 돌려준다. 원격 화면이나 출력에서 코드를 추출하지 않는다. 사용자는 해당 메인 탭에서 설치한 Bash 처리기를 직접 호출해 로컬 UI의 코드를 숨김 입력한다. 처리기는 코드가 가리키는 소켓의 소유 UID를, 제어 실행기는 피어 UID와 코드 일치·만료 여부를 확인한다. 양쪽이 같은 시험 UID가 아니면 연결을 거부한다. 같은 노드에 탭이 두 개면 입력한 탭에서만 짝을 맺고, 앱에서 선택한 탭과 실제 입력 탭이 같을 때만 연결을 확정한다(로컬 터미널 입력 출처로 확인). 코드는 즉시 소비하고 로그·모델·명령 인자에 남기지 않는다. 다음 예약부터 `claim → 승인 결과 → started/output/exited`를 이 소켓과 A02 제어 세션으로 중계한다. 공유 모드에서 제어 세션은 자식을 시작하지 않는다. 모드 해제·탭 종료·채널 단절 시 예약을 폐기하고 소켓과 바인딩을 닫는다. 준비가 불완전하면 제안만 남긴다.
3. **입력 경쟁.** `내 셸 사용`은 현재 백엔드 세션 ID·세대에만 연결한다. UI에서 `compositionstart`, 키 입력, 붙여넣기 시작을 입력 세대에 반영한다. 단일 세션 입력 큐에서 예약 키와 일반 입력을 직렬화한다. 물리 키를 통과시키기 전에 조합·대기 입력이 없고 같은 탭인지 확인한다. 처리기가 빈 줄을 확인한 후 인증 채널로 예약을 요청하면 Rust가 동일 입력 세대·승인 ID·세션·모드·정책을 한 번에 비교하고 소비한다. 일반 입력이 먼저면 공유 요청을 취소하고 그 입력을 그대로 전달한다. 예약이 먼저면 시작 인계 동안만 해당 탭의 새 입력을 잠시 막고 ‘시작 중’을 표시한다. 나중에 암호 프롬프트로 키를 재생하는 큐는 만들지 않는다. 승인 대기 중 탭 이탈·연동 해제·만료는 예약을 취소한다. **실행 시작 후** 탭 이동은 실행 대상이나 상태 구독을 바꾸지 않는다.
4. **실행과 출력.** 처리기는 현재 셸의 작업 디렉터리·사용자·터미널에서 A02와 같은 고정 실행기를 호출한다. 제안 문자열을 `eval`하거나 메인 PTY로 명령+Enter를 합성하지 않는다. 실제 명령은 메인에 한 번 표시한다. 실행기가 직접 시작한 자식의 stdout/stderr 파이프를 읽을 수 있는 고정 조회라면 그 바이트를 메인으로 내보내면서 작업 ID가 붙은 사본만 인증 채널로 보낸다. 그 외에는 `메인 탭에서 보기`로 연결한다. 오른쪽 뷰는 메인 PTY 전체를 구독하지 않는다. 사용자 키·다른 작업 출력은 채팅에 전달하지 않는다. 중지는 A02의 동일 작업 ID와 종료 증거를 쓰고 입력 권한은 인계 종료·오류 시 돌려준다.

## 검증과 완료 증거

5. **자동:** 구현 후 `cargo test --manifest-path src-tauri/Cargo.toml`, `npx vitest run src/features/ai`로 경쟁 순서를 바꿔 검사한다. 시작 횟수·출력 구독 대상·세션 세대를 단언한다. **실기기:** `npm run tauri dev`로 노드 A·B를 열고 오른쪽 위에서 `가동 시간 확인`을 요청한다. 아래 각 행을 **Windows 11 / Ubuntu 24.04 × 기본 / Auto / Bypass × 전용 / 공유** 각각에 기록한다. 셀마다 OS·모드·노드 별칭·요청 ID·관찰·판정·증거 위치를 적는다. 하나의 성공 영상으로 다른 조합을 채우지 않는다.

| T7 시험 입력 | 관찰할 결과 |
|---|---|
| A에서 정확히 허용한 `uptime`, 같은 조회 반복, B 또는 재연결한 A에서 반복 | 대상·실제 명령·한국어 해석이 먼저 보인다. 전용은 오른쪽만, 공유는 지정한 메인에서 한 번만 실행한다. Bypass의 반복 승인 범위가 다른 세션으로 넘어가지 않는다. |
| 명시 차단, 미등록 조회, 복합 입력, 상태 변경 제안, 금고·승격 요구 | 차단 우선. 미등록·복합은 자동 전송 0건, 지원하는 상태 변경은 별도 확인. 금고·승격 자동 승인 0건. Auto 권고나 모델 오류로 결과가 뒤집히지 않는다. |
| A에 한글 조합·미제출 텍스트·`vim`·암호 입력·실행 중 작업을 각각 준비하고 공유 제안. 입력 직전 붙여넣기와 승인도 교차 | 공유는 제안만 남고 기존 줄·프로그램에 AI 바이트가 섞이지 않는다. 전용에서는 A 메인의 키·포커스를 유지한다. 암호 대신 시험용 비밀 없는 숨김 입력을 사용한다. |
| 실행 중 B로 이동, 집중 보기 왕복, A에 별도 백그라운드 출력 발생 | 대기·실행 모두 기본 보기의 네 영역 유지. 상태줄 왼쪽만 B로 전환. 분리할 수 없는 바이트는 메인에만 표시한다. |
| 오래 걸리는 고정 시험 작업 중지, 별도 실행에서 종료 확인 전 연결 단절 | `중지 요청됨`과 증거가 있는 `종료됨`, 단절의 `종료 확인 불가`를 구별한다. 메인 셸과 노드 B의 독립 세션이 남는다. |

6. 두 OS에서 AI 설정을 끄고 메인 셸의 한글 입력과 수동 명령도 시연한다. 실제 세션별 시작 횟수, 위 상태 변화, 양쪽 탭 입력이 보이는 마스킹된 기록을 제출한다. 공급자·장비·권한이 없는 조합은 `미실행(사유)`이며, macOS는 후속 실기기 검증이다.
