# A03 지정한 중앙 세션에서 승인 작업을 한 번 실행하고 T7 판정하기
선행: A02

사용자가 중앙에서 두 번째 터미널을 직접 열고, 필요하면 두 터미널을 수직 구분선으로 나뉜 좌우 영역에 직접 배치한다. AI 채팅에서 검토한 작업은 사용자가 지정·확인한 중앙 세션에서 한 번만 실행된다. 오른쪽은 AI 채팅/SFTP 탭이며 조회 제안, 작업 상태와 중지는 채팅 안에 둔다.

**준비물:** A02의 정책·작업 실행기·인증된 제어 채널, 승인된 비운영 Linux 노드 A·B와 시험 계정, 네이티브 Windows 11 및 Ubuntu 24.04 GNOME Wayland. 구현 후 사용할 명령은 `app/` 기준이다.

## 인수 조건

- **Given** 사용자가 A의 백엔드 세션 ID·세대를 대상으로 확인하고 승인 ID를 받았다. **When** 실행 전이나 실행 중 B로 포커스를 옮긴다. **Then** 포커스는 키보드 입력 위치만 바꾼다. 승인 대상은 A이며, A에서 준비가 확인돼 실행한 경우에만 A에서 1회 시작한다. 실행 중 상태줄 왼쪽은 B, 오른쪽은 A의 실제 작업 상태다.
- **Given** 승인이 만료됐거나 같은 노드의 다른 세션을 사용 중이거나 A가 한글 조합·줄 편집·`vim`·암호 입력·다른 작업 실행 중이다. **When** 제안을 확인하거나 실행을 시도한다. **Then** 기존 입력을 보존하고 제안과 실행 불가 상태만 남긴다. 준비를 확인할 수 없는 경우도 동일하다.

## 구현 순서

1. **Red — 포커스와 권한 분리.** `src-tauri/src/ai/`에서 포커스 이동, 명시적 대상 재선택, 승인 중복·만료, 같은 노드의 다른 세션, 재연결, 입력 경합을 분리해서 시험한다. `src/features/ai/`에서 채팅 검토와 포커스 이동이 기존 승인 대상을 바꾸지 않는지, 모델·CLI·채팅에서 일반 PTY 쓰기가 0건인지 확인한다.
2. **Green — 세션 지정.** 사용자가 이미 연 중앙 터미널을 실행 대상으로 명시하고 실제 연결과 세션을 확인한다. 대상 선택은 실행 승인이 아니다. 로컬 UI는 A01의 제안 결정을 참조해 작업·인자·정책과 정확한 백엔드 세션 ID·세대를 묶은 실행 승인 ID를 발급한다. 다른 탭에 포커스를 줘도 이 바인딩은 유지된다. 사용자가 실행 대상을 명시적으로 바꾸면 이전 대기 승인을 폐기하고 새 대상으로 다시 검토한다. 세션 닫기·재연결·연동 해제·만료 후에는 새 확인이 필요하다. 같은 호스트명·계정·연결 프로필은 같은 세션의 증거가 아니다. 자동 SSH는 사용하지 않는다. 향후 별도 명시 동작으로 검토할 수 있지만 이번 범위에는 없다.
3. **준비와 인증.** 시험 계정에 사용자가 설치한 Bash 연동에서 시작한다. 관리자가 `src-tauri/resources/ai/shared.bash`와 A02 고정 실행기를 설치한다. A02의 제어 실행기는 노드의 사용자 전용 런타임 디렉터리(0700)에 채널별 Unix 소켓(0600)을 열고 일회용 연결 코드를 Rust에 돌려준다. 사용자가 선택한 중앙 탭에서 처리기를 직접 호출해 코드를 숨김 입력한다. 처리기는 소켓 소유 UID를, 실행기는 피어 UID와 코드 일치·만료를 검사한다. 앱은 로컬 터미널 입력 출처로 실제 입력 탭이 지정한 세션과 같을 때만 바인딩을 확정한다. 코드는 즉시 소비하고 로그·모델·명령 인자에 남기지 않는다. 연동 해제·세션 종료·채널 단절 시 예약·소켓·바인딩을 정리한다.
4. **입력 경합과 실행.** 사용자가 지정한 셸의 빈 프롬프트에서 직접 예약 키를 누른다. Bash `bind -x` 처리기가 포그라운드와 빈 `READLINE_LINE`을 확인한 뒤 인증 채널로 `claim`을 보낸다. `$`, OSC, 출력의 `ready`는 준비 증거가 아니다. 세션별 입력 큐에서 물리 예약 키와 일반 키·붙여넣기를 직렬화하고, 키 입력·붙여넣기·IME 조합 시작은 입력 세대에 반영한다. Rust는 동일 입력 세대·승인 ID·준비 기한·세션·정책을 한 번에 확인하고 소비한다. 일반 입력이 먼저면 예약을 취소하고 입력을 그대로 전달한다. 예약이 먼저면 시작 인계 동안 해당 세션에 `시작 중`을 표시하고 추가 입력을 잠시 막는다. 막은 키를 나중에 재생하지 않는다. 승인과 작업은 인증 채널만 통과한다. AI나 앱이 일반 PTY에 명령·문자·Enter·예약 키를 주입하거나 제안 문자열을 `eval`하는 경로는 없다.
5. **출력과 중지.** 선택한 셸의 작업 디렉터리·사용자·터미널에서 A02와 같은 고정 실행기를 호출한다. 제어 채널은 작업을 중계하며 별도 자식을 시작하지 않는다. 실제 명령을 중앙에 1회 표시한다. 실행기가 직접 수집한 작업 ID별 출력만 채팅에 연결하고, 분리할 수 없는 출력은 중앙 탭에서 본다. 일반 터미널 기록·사람 키 입력·다른 작업 출력은 채팅이나 모델에 전달하지 않는다. 중지는 A02의 같은 작업 ID와 종료 증거를 사용한다. 인계 후 종료·오류 시 입력을 돌려준다. 금고·승격은 원래의 별도 사용자 승인과 로컬 인증 경계에 둔다.

## 검증과 완료 증거

6. **자동:** 구현 후 `cargo test --manifest-path src-tauri/Cargo.toml`, `npx vitest run src/features/ai`로 아래 경쟁 순서와 세션별 실행 횟수를 검사한다. **실기기:** `npm run tauri dev`로 승인된 노드 A·B를 사용자가 직접 열고 중앙 좌우에 배치한다. AI 채팅에서 `가동 시간 확인`을 요청한다. 아래 각 행을 **Windows 11 / Ubuntu 24.04 × 기본 / Auto / Bypass** 각각에 기록한다. OS·정책·세션 ID·세대·승인 ID·시작 횟수·관찰·판정·증거 위치를 남긴다. 하나의 성공으로 다른 조합을 채우지 않는다.

| T7 시험 입력 | 관찰할 결과 |
|---|---|
| **Given** A를 명시적으로 지정해 `uptime` 승인 ID를 받았다. **When** 실행 전에 B로 포커스를 옮겼다가 A에서 직접 준비를 확인하고 실행한다. | **Then** 정확한 대상·실제 명령·한국어 한 줄 해석이 채팅에 먼저 보인다. 포커스만으로 승인 대상이 바뀌거나 실행이 시작되지 않는다. A에서만 1회, B에서는 0회다. 같은 승인 ID를 다시 제출해도 추가 실행은 0회다. |
| **Given** A 승인 또는 Bypass 반복 허용이 있다. **When** 승인 만료 후, 같은 노드의 다른 세션, 재연결한 A, 명시적으로 바꾼 대상에서 각각 이전 ID로 실행을 시도한다. | **Then** 기존 승인으로 작업 시작 0회, AI의 PTY 쓰기 0건이다. 다시 실행하려면 해당 세션을 지정·확인하고 새 승인을 받는다. |
| **Given** 지정한 셸에 한글 조합·미제출 텍스트·`vim`·숨김 입력·실행 중 작업 또는 준비 불명 상태가 있다. **When** 제안을 검토하거나 실행을 시도한다. 붙여넣기와 준비 확인의 순서도 바꿔 본다. | **Then** 준비 조건이 충족되기 전에는 제안만 남고 사람의 입력과 프로그램 상태를 보존한다. 먼저 들어온 일반 입력은 원래 세션에 전달되고 오래된 예약으로 시작하지 않는다. 모델 문자·Enter·예약 키의 일반 PTY 쓰기는 0건이다. 암호 대신 비밀 없는 숨김 입력을 사용한다. |
| 명시 차단, 미등록 조회, 복합 입력, 상태 변경 제안, 금고·승격 요구 | 차단이 우선이다. 미등록·복합의 자동 전송 0건, 지원하는 상태 변경은 별도 확인, 금고·승격 자동 승인 0건이다. Auto 권고나 모델 오류로 판정이 바뀌지 않는다. |
| 실행 중 B로 포커스 이동, 집중 보기 왕복, A의 별도 백그라운드 출력 | 오른쪽은 AI 채팅/SFTP 탭뿐이다. 상태줄 왼쪽은 B, 오른쪽은 A의 작업 상태다. 중앙 좌우 배치와 각 세션은 유지되고 분리할 수 없는 바이트는 중앙에만 표시된다. 추가 SSH 접속은 0건이다. |
| 고정 시험 작업 중지, 별도 실행에서 종료 확인 전 연결 단절 | `중지 요청됨`과 증거가 있는 `종료됨`, 단절 시 `종료 확인 불가`를 구별한다. 중앙의 다른 세션은 계속 동작한다. |

7. 두 OS에서 AI 설정을 끄고 메인 셸의 한글 입력과 수동 명령도 시연한다. 세션별 시작 횟수와 양쪽 입력·작업 상태가 보이는 마스킹된 기록을 제출한다. T7은 현재 `미실행`이다. 공급자·장비·권한이 없는 조합은 `미실행(사유)`으로 남기고, macOS는 후속 실기기 검증으로 분리한다.
