# A02 승인한 작업을 AI 전용 세션에서 한 번 실행하기
선행: A01

사용자가 선택한 비운영 대상에서만 오른쪽 아래 전용 셸을 열고 실제 명령·출력·중지 결과를 본다. 메인 셸에서는 동시에 입력할 수 있다.

**준비물:** A01의 실제 제안 경로, C02의 SSM 세션 생성·정리 코드, 별도 권한 승격 없이 `uptime`이 가능한 승인된 Linux 시험 노드 두 개, 네이티브 Windows 11 및 Ubuntu 24.04 GNOME Wayland. 아래 명령은 구현 후 `app/`에서 실행한다.

## 인수 조건

- **Given** 전용 모드에서 노드 A를 선택하고 조회를 승인했다. **When** 채팅에서 `가동 시간 확인`을 요청하고 메인 탭 B에 입력한다. **Then** 오른쪽 아래에만 A의 실제 `uptime`과 응답이 한 번 나오고 B는 입력과 포커스를 유지한다. 선택 전에는 전용 세션이 없다.
- **Given** 승인 후 재연결했거나 명시 차단된 요청이다. **When** 같은 ID로 재전송하거나 모델이 실행을 권한다. **Then** 전송 건수는 0이다. **Given** 실행 중 중지를 눌렀다. **When** 종료 확인 전에 연결이 끊긴다. **Then** `중지 요청됨` 뒤 `종료 확인 불가`가 표시된다.

## 구현 순서

1. **Red.** `src-tauri/src/ai/`에 A01 승인 기록을 두 번 소비하는 경쟁, A 승인으로 B를 요청하는 경우, 정책 변경, 세션 종료·재연결 뒤 반복 요청을 테스트한다. 허용된 첫 요청만 전용 세션으로 한 번 전달되어야 한다. `src/features/ai/`의 Vitest는 출력 도착 때 메인 포커스와 하단 상태줄 왼쪽이 그대로인지 검사한다.
2. **Green — 대상과 권한.** 사용자가 대상과 전용 모드를 선택하면 Rust가 C02의 앱 소유 SSM 세션을 별도로 연다. 메인과 다른 백엔드 발급 세션 ID를 사용한다. 승인 당시 세션이 없었다면 실제 연결의 노드·계정·리전과 새 세션을 화면에서 확인한 뒤 승인한다. 원본 승인, 대상·세션 세대, 정책 버전, 작업과 인자, 모드를 잠금 안에서 대조하고 1회 소비한다. 쓰기 결과가 불명확해도 다시 보내지 않는다. CLI와 모델은 A01 제안만 제출하고 세션 핸들·일반 키 스트림·실행 API·AWS 자격 증명·금고·권한 설정을 받지 않는다.
   - **시험 노드 최초 준비:** `src-tauri/resources/ai/ZzabbaAiControl.json`에 운영자가 배포할 SSM `Session` 문서(`Standard_Stream`)를 작성한다. 제한된 시험 사용자로 실행하고 Linux 시작 명령은 `exec /usr/local/libexec/zzabba-ai-control` 하나로 고정한다. 사용자 입력 파라미터와 일반 셸 폴백을 두지 않는다. 관리자가 `src-tauri/src/bin/zzabba-ai-control.rs`에서 빌드한 Linux 실행 파일을 관리자 소유·시험 사용자 쓰기 불가로 설치하고, 승인한 노드와 해당 문서에만 제어용 `StartSession`, 자기 세션에만 종료 권한을 준다. 앱·모델에는 문서 편집·배포 또는 IAM 변경 권한을 주지 않는다.
   - **열기:** Rust는 C02의 기존 프로필·리전·대상으로 공식 CLI `aws ssm start-session`을 실행하되 이 세션에만 `--document-name ZzabbaAiControl`을 지정한다. 별도 포트·SSH·SFTP는 쓰지 않는다. `src-tauri/src/ai/control.rs`가 이 세션의 유일한 입출력 소유자다. 실행기는 터미널 에코를 끄고 준비 메시지를 보낸다. 앱은 버전과 새 난수를 교환하고 이 채널을 계정·리전·노드·로컬 세션 세대에 묶는다. 플러그인 시작 안내는 준비 전 표시용으로만 취급한다. 설치 누락·권한 거부·에코 해제 실패·협상 실패 시 해당 세션을 정리하고 제안만 제공한다.
3. **실행 범위.** Rust가 지원하는 작업 표에서 실행할 프로그램과 인자를 결정한다. 예: 승인된 노드의 신뢰된 설치 경로에서 `uptime`을 인자 없이 실행한다. 셸의 별칭·함수·사용자 PATH에 기대지 말고 실제 전달할 절대 경로도 승인 카드에 표시한다. 모델·CLI·채팅의 셸 문자열, 임의 경로·옵션·환경 변수는 실행기에 전달하지 않는다. 고정 조회와 사용자가 요청하고 작업 표에 명시된 방어·운영 작업만 허용한다. 상태 변경은 매번 정확한 대상과 인자를 확인하고 금고·승격 요구는 별도 사용자 흐름에 남긴다. 미등록·복합 명령은 검토로 끝낸다.
4. **규칙.** 기본은 명시 차단 → 정확히 허용한 조회 → 나머지 확인 순서다. Auto에서 별도로 승인된 System One이 있으면 일치한 규칙 옆에 해석·권고만 붙인다. 미설정·오류 때도 같은 규칙을 적용한다. Bypass는 사용자가 연 같은 세션·같은 대상·같은 조회와 인자에 대한 기존 승인만 재사용한다. 반복 때도 카드를 먼저 표시하고 새 실행 ID를 한 번만 소비한다. 노드 전환·재연결·정책 변경·모드 해제 시 반복 허용을 폐기한다. 모델이 스스로 후속 작업을 시작할 경로는 없다.
5. **입출력·중지.** 준비 이후에는 개행으로 끝나는 길이 제한 JSON 프레임만 교환한다. `start → started → output(0회 이상) → exited` 순서이며 각 프레임에 채널 난수·작업 ID·방향별 순번을 넣는다. 실행기는 고정 작업 자식의 stdout/stderr를 별도 파이프로 읽어 바이트를 Base64로 감싼 `output`만 만든다. 앱은 채널·ID·순번·상태를 검사한 뒤 출력 페이로드만 오른쪽 아래에 표시한다. 자식이 출력한 JSON도 데이터다. 플러그인 안내·PTY 에코·다른 작업 ID를 프레임으로 받아들이지 않는다. 잘린 줄·순번 누락·예상 밖 입력이면 처리를 중단한다. 이 뷰의 키와 붙여넣기는 전송하지 않는다. 사용자가 중지를 누르면 `중지 요청됨`으로 표시하고 현재 작업의 `stop`만 보낸다. 실행기는 그 자식을 중지하고 회수한 뒤 `exited`를 보낸다. 이때만 `종료됨`으로 표시한다. 확인 전 단절은 `종료 확인 불가`다. 닫을 때 실행기는 소유 자식만 종료·회수하고 Rust는 해당 제어 세션만 정리하며 반복 승인도 폐기한다. 메인 탭은 유지한다.

## 검증과 완료 증거

6. **자동:** 구현 후 `cargo test --manifest-path src-tauri/Cargo.toml`과 `npx vitest run src/features/ai`로 중복 소비, 위조 종료 출력, 정책, 표시·포커스를 검사한다. **실기기:** 두 OS에서 `npm run tauri dev`로 실제 노드 A·B를 연다. 대기 → A 전용 조회 → B에서 수동 `whoami` → 탭 이동·집중 보기 왕복 → A 결과를 녹화한다. 오래 걸리는 무해한 고정 시험 작업(예: 노드에서 허용한 30초 대기)으로 중지와 확인 채널 단절을 따로 재현한다. 세 모드의 첫 승인·반복·거절, 실제 작업 ID별 자식 시작/종료 건수, 하단 실제 대상, 영향 없는 B를 기록한다. 자격 증명·출력 원문 전체는 수집할 필요가 없다. OS별 미확인 항목은 `미실행(사유)`, macOS는 후속이다.
