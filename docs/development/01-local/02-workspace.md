# L02 두 로컬 셸을 유지하는 4분할 작업 화면과 창 제어

선행: L01

**사용자 결과:** 로컬 탭 두 개를 오가며 셸을 쓰고, 집중 보기에서 한 탭을 넓혔다가 입력과 패널 크기를 그대로 되찾는다. 제목줄의 창 버튼은 실제 OS 창을 제어한다.

**준비물:** L01의 실세션, 네이티브 Windows 11과 Ubuntu 24.04 GNOME Wayland의 닫아도 되는 시험 창, 비교용 별도 창, 키보드·마우스. 트리에는 로컬 대상만 두고 오른쪽 AI 채팅과 AI 터미널은 미연결로 둔다. AWS·AI 연동이나 연결 마법사는 이 티켓의 준비물이 아니다. 아래 명령은 구현 시점에 `app/`에서 실행한다.

## 인수 조건

| Given | When | Then |
|---|---|---|
| 기본 4분할과 로컬 탭 A·B | 트리를 280→340 CSS px로 넓히고 A에 제출 전 텍스트를 입력한 뒤 집중 보기를 왕복 | 핸들과 트리 끝이 일치한다. 실제 창 크기, 활성 탭·세션 ID, 미제출 입력, 이전 트리·AI 열 너비와 상하 비율이 유지된다. |
| A에서 지연된 출력이 예정되고 B에 커서가 있음 | A의 출력이 도착한 뒤 B에 문자를 입력 | 포커스와 입력은 B에 남고 A를 다시 열면 A의 출력이 보인다. 오른쪽 위에 입력한 채팅 초안은 어느 PTY에도 도달하지 않는다. |
| 탭 목록이 넘치는 좁은 창 | 탭·버튼 클릭, 핸들 드래그·더블클릭, 최소화·복원 후 닫기 | 목록만 가로로 스크롤된다. 핸들/빈 여백에서만 창이 움직이며 버튼은 고정된다. `×`는 현재 창만 닫는다. |
| A 셸이 종료되거나 마지막 탭이 닫힘 | 상태줄 확인 | 왼쪽은 선택한 탭의 실제 상태 또는 `연결 없음`, 오른쪽은 `AI 전용 셸 · 대기`다. 상태줄은 출력 스크롤과 무관하게 창 아래에 있다. |

## 개발 순서

1. **Red — 화면 전환과 입력 경계를 시험한다.** `app/src/features/workspace/`에 Vitest로 A/B 탭의 서로 다른 L01 세션 ID, 활성 탭, 트리·오른쪽 열·상하 경계 값을 넣는다. 집중 보기 왕복과 탭 전환 뒤 같은 값·채팅 초안이 남고 PTY 열기/닫기 호출 수가 늘지 않는 시험부터 작성한다. 비활성 탭의 출력·종료 통지가 활성 탭이나 키보드 포커스를 바꾸지 않는 경우도 둔다. 프런트엔드 시험은 호출·상태만 판정하며 창 동작은 아래 T8에서 판정한다.
2. **Green — 화면을 세 줄로 구성한다.** `app/src/features/workspace/`의 React 뷰와 CSS Grid에 제목줄, 남은 높이의 작업 영역, 전체 폭의 24 CSS px 상태줄을 둔다. 작업 영역은 왼쪽 트리·가장 넓은 가운데 탭·오른쪽 상하 두 영역이다. 왼쪽 핸들과 트리는 같은 너비 값(기본 280px), 오른쪽은 360 CSS px·상하 1:1에서 시작한다. 포인터 드래그로 열 경계와 오른쪽 가로 경계를 조절하고 값은 작업 화면에 보관한다. 트리는 `그룹 → 로컬 대상`, 글자 15px·행 36px, 행 전체 선택·화살표 탐색·Enter/더블클릭 열기를 제공한다. 터미널 글자 크기는 UI 배율과 따로 유지한다.
3. **탭 수명과 보기를 분리한다.** 트리에서 같은 로컬 대상을 두 번 열어도 별도 세션과 탭을 만든다. 탭 콘텐츠와 L01 터미널은 세션 ID로 연결하고, 선택 또는 보기 전환으로 컴포넌트를 재생성하지 않는다. 보여 줄 때만 실제 영역에 맞춰 `fit`·PTY resize를 요청한다. 집중 보기는 트리와 핸들의 이름, 오른쪽 두 영역만 접고 제목줄·상태줄·탭 뒤의 창 이동 여백을 유지한다. 복귀할 때 접기 전 크기와 입력을 복원한다. 오른쪽 위 채팅 입력은 로컬 초안에만 연결하고, 아래에는 `대기`를 표시한다. 출력 처리에서 `focus()`를 호출하지 않는다.
4. **상태줄을 데이터에 연결한다.** 왼쪽에는 현재 탭의 대상·접속 경로·상태(예: `내 PC · 로컬 · 연결됨`)를 L01 세션 상태에서 읽고, 종료·단절·탭 전환·마지막 탭 닫기를 반영한다. 오른쪽은 AI 상태가 소유하는 자리이며 이 단계에서는 대기다. 상태줄을 스크롤 컨테이너 바깥에 두고 명령 원문, 자격 증명, 도구 버튼을 넣지 않는다.
5. **창 동작만 네이티브 API로 보낸다.** Windows·Linux 제목줄은 `핸들 | 탭 목록 | 이동 여백 | 뷰 전환 | 최소화 | 최대화/복원 | 닫기` 순이다. 탭 목록만 줄고 스크롤되며, 너비가 달라지면 선택한 탭을 다시 드러낸다. 핸들과 빈 여백의 마우스 누름에서 첫 클릭은 이동을, 두 번째 클릭은 Windows·Linux의 최대화/복원을 요청한다. 창 버튼과 이동 영역은 `workspace_window`에 동작만 보낸다. Rust는 IPC 발신 창에서만 Tauri 창 API를 실행하며, 호출 오류는 상태줄에 표시한다. 뷰 전환은 창 명령과 별개다. macOS는 왼쪽 기본 신호등 공간을 남기고 오른쪽 창 버튼을 생략한다.

## T8 검증과 완료 증거

1. **자동:** F00의 Vitest 실행 명령으로 `src/features/workspace/` 시험을 실행한다. Tab 키로 도달하는 창 버튼의 이름·클릭 대상도 확인한다. 닫기 오류를 반환하는 창 어댑터로 시험해 실제 창이 닫힌 것처럼 탭을 비우지 않는지 본다.
2. **실기기:** 두 OS 각각 `npm run tauri dev`로 연다. 로컬 탭 A에서 PowerShell은 `Start-Sleep 5; echo A_DONE`, Bash는 `sleep 5; echo A_DONE`을 실행하고 B로 옮겨 `echo B_READY`까지만 친다. A 출력 중에도 B 입력 위치가 그대로인지 확인한다. 채팅 초안에 다른 표식을 입력하고 탭을 오가며 어느 셸에도 그 표식이 들어가지 않았는지 본다.
3. 트리를 280→340px로 바꾸고 오른쪽 너비와 비율도 바꾼다. 핸들·트리의 끝 좌표와 경계 값을 WebView 개발 도구의 CSS px로 기록한다. B에서 집중 보기를 왕복하고 이전 값, 미제출 입력, 활성 탭, 상태줄 위치를 비교한다. B에서 Enter를 눌러 결과를 확인하고 A에 `A_DONE`이 남았는지 본다.
4. 핸들 및 탭 뒤 빈 곳에서 창을 끌고 더블클릭으로 최대화·복원한다. 탭이나 뷰 버튼 클릭 시 창이 이동하지 않는지 확인한다. 창을 좁히고 필요하면 로컬 탭을 더 열어 탭 목록만 넘치게 만든다. 버튼이 보이는 상태에서 최소화→OS 작업 표시줄/개요에서 복원→최대화→복원한다. 마지막 탭을 닫아 `연결 없음`을 확인하고, 시험 창의 `×`로 그 창만 닫는다. 비교용 창은 그대로 있어야 한다.
5. **완료 증거:** `T8 / Windows 11`, `T8 / Ubuntu 24.04 GNOME Wayland`별로 OS·WebView 버전, 전환 전후 경계 값, 탭·입력·상태줄, 실제 창 이동과 종료 대상을 확인할 수 있는 캡처 또는 짧은 녹화, 자동 시험 결과를 첨부한다. 현재 둘 다 `미실행`이다. 브라우저 미리보기나 API 호출 횟수만으로 T8을 통과 처리할 수 없다. macOS는 장비 확보 후 실기기로 확인한다.

### L02 작업자 검증

- 자동: `npm test -- src/features/workspace/Workspace.test.tsx`에서 L01에 상태줄·연결 트리·제목줄이 없어 3개 시험이 실패했다(Red). L02 구현 뒤 `npm test`는 7개, `cargo test --locked --manifest-path src-tauri/Cargo.toml`은 3개가 통과했다. `npm run build`는 통과했고 Vite의 500 kB 청크 경고가 남았다.
- Windows 11 Pro `10.0.26200`, WebView2 `157.0.4341.60`, PowerShell: 비교 창과 충돌한 기본 실행은 `0x8007139F`로 종료했다. 별도의 `WEBVIEW2_USER_DATA_FOLDER`와 개발 포트로 시험 창을 분리한 뒤 1200×720 CSS px에서 Rust 세션 `0`·`1`, `A_DONE` 출력, B의 미제출 입력과 채팅 초안을 관찰했다. 홀로 남은 이동 여백과 핸들의 더블클릭, 최대화 버튼은 실제 창을 4096×1680으로 확대하고 1200×720으로 복원했다. 마지막 탭을 닫으면 `연결 없음`이 표시됐으며 창의 닫기 버튼을 누른 뒤 비교 창만 남았다.
- Windows 집중 보기: 트리·핸들의 끝이 함께 280→340px로 이동했다. 집중 보기 전후 트리 340px, AI 열 340px, 채팅 높이 361.9/658px(55%), 활성 세션 `1`, 터미널 포커스 및 하단 24px 상태줄을 확인했다. 집중 보기 도중 창 크기도 1200×720으로 유지됐다.
- T8 전체 판정: Windows는 OS에서 직접 끌기, 오른쪽 두 경계 포인터 조절, 최소 창 탭 스크롤, 최소화→작업 표시줄 복원, A의 출력 시점과 B 입력의 교차 순서가 미실행이다. Ubuntu 24.04 GNOME Wayland는 T8의 실기기 절차 전체가 미실행이다. macOS 신호등은 M01에서 확인한다.

독립 리뷰 반영 후 Windows 합성 트리에서 `npm test` 16개, `npm exec -- tsc --noEmit`, `cargo test --locked --manifest-path src-tauri/Cargo.toml terminal::tests -- --test-threads=1` 7개가 통과했다. 실창에서 새 발신 창 명령의 핸들·여백 더블클릭과 최대화 버튼으로 1200×720 → 4096×1680 → 1200×720 전환을 확인했다. 직접 창 끌기와 Wayland 실기기는 위 미실행 상태를 유지한다.
