# L03 한글 입력과 연속 출력을 지키는 메인 터미널 — T1 로컬·T2

선행: L02

**사용자 결과:** 가운데 로컬 셸과 네 CLI의 원래 대화형 화면에서 한글을 조합·수정하고 붙여넣어 한 번만 제출한다. 출력이 몰려도 응답을 취소하고 같은 셸에서 다음 작업을 시작할 수 있다.

**준비물:** L01의 PTY·L02의 두 탭, 물리 키보드, Windows 11의 네이티브 PowerShell·한국어 두벌식 IME·WebView2, Ubuntu 24.04 GNOME Wayland의 네이티브 Bash·IBus Hangul 두벌식·WebKitGTK. 각 OS에 사용자가 설치·인증한 `claude`, `codex`, `omp`, `opencode`, 승인된 시험 계정과 비어 있는 시험 디렉터리를 준비한다. 일반 OS 터미널에서 각 도구를 대화형으로 열어 응답·취소·정상 종료 동작과 해당 버전의 키 안내를 먼저 확인한다. 외부 CLI의 공급자 연결과 앱의 AI 패널은 별개다. 앱은 도구를 번들하거나 자동 설치하지 않으며 AWS·AI 패널은 연결하지 않는다. 아래 명령은 구현 시점에 실행하며 개발 명령의 기준 경로는 `app/`이다.

## 인수 조건

| Given | When | Then |
|---|---|---|
| 로컬 프롬프트의 기존 문자 뒤에 `한` 조합 중 | Backspace → `ㄴ` → 공백 → Backspace 두 번 | 조합 중 `한 → 하`, 재조합 후 `한` 하나와 공백 하나, 삭제 후 기존 문자만 남는다. |
| 실제 CLI 입력창에 포커스가 있음 | 두 줄을 붙여넣고 확인 후 제출, 응답 중 크기 변경·탭 왕복·취소 후 새 요청 전송 | 중복·조기 제출 없이 한 번 전달된다. 커서·줄바꿈과 입력 위치가 복원되고 취소 뒤 새 응답을 받는다. |
| 렌더러의 처리 완료 통지가 늦어지는 세션 | 자식이 여러 출력 조각을 계속 생성 | 미확인 바이트가 정한 상한 안에 머물고 Rust 읽기가 대기한다. 처리 완료 후 같은 순서로 재개하며 중복·손실이 없다. 대기 중에도 키 입력·탭 닫기는 동작한다. |
| 출력 대기 중 실제 채널 단절 또는 자식 종료 | 마지막 상태를 확인 | 지연은 세션을 유지한다. 채널 실패는 단절, 자식의 대기 결과는 종료로 구분하고 종료 코드와 마지막 출력을 뒤섞지 않는다. |

## 개발 순서

1. **Red — 에코가 아닌 경계에서 센다.** `app/src/features/terminal/`에 Vitest 시험을 둔다. xterm의 입력 `onData` 한 번에 L01 writer 전달 한 번, 탭을 왕복한 뒤에도 한 번인지 본다. 붙여넣은 두 줄과 `Ctrl+C`가 원래 바이트 순서로 한 세션에만 가는지 검사한다. `app/src-tauri/src/terminal/`에는 UTF-8 한 글자와 ANSI 제어 시퀀스를 중간에서 나눈 고정 바이트열, 연속된 번호와 마지막 표식을 준비한다. 읽기 한도를 채우고 수신 측 처리 완료를 보류했다가 재개하는 시험에서 전송 순서·최대 미확인 바이트·최종 바이트 일치 여부를 검사한다. 느린 세션 A가 B를 막는 경우와 대기 중 닫기도 재현한다. 이 시험은 물리 IME나 실제 CLI의 시험 결과와 구분한다.
2. **Green — 단일 입력 경로를 유지한다.** xterm 자체 입력 요소에 포커스를 주고 조합 중 글자는 WebView IME와 xterm이 처리하게 한다. 앱은 `term.onData`가 내놓은 텍스트·제어 입력만 해당 PTY의 UTF-8 writer에 순서대로 넘긴다. `keydown`, `beforeinput`, `compositionend`, `paste`에서 같은 글자를 다시 쓰거나 키 이벤트로 Enter/Backspace를 합성하면 입력이 겹친다. 네이티브 붙여넣기는 xterm에 맡기고 bracketed paste의 제어 문자·줄바꿈을 보존한다. 대화형 프로그램이 에코와 대체 화면을 그리므로 앱에서 입력 문자를 `term.write`로 미리 그리지 않는다. 세션 수명당 구독 하나를 유지하고 실제 닫기에서 해제한다. React 재렌더·탭 왕복·보기 전환 때 writer가 중복 등록되지 않아야 한다.
3. **Green — 출력의 읽기 한도를 렌더러와 연결한다.** 세션별 고정 크기 조각을 L01의 순서 보존 채널로 넘기고, 프런트엔드는 `Uint8Array` 그대로 `term.write(bytes, callback)`에 넣는다. 조각별 문자열 변환이나 ANSI 필터를 끼우면 경계에 걸친 문자·화면 제어가 깨진다. Rust reader에 바이트 상한을 두고 남은 허용량 이하만 읽는다(시험 시작값 예: 조각 최대 16 KiB, 미확인 합계 256 KiB). 콜백은 화면 그리기 횟수가 아니라 xterm 파서의 처리 완료를 알린다. 프런트엔드가 그때까지 처리한 누적 바이트 위치를 별도 IPC로 확인해 주면 Rust가 그만큼 한도를 돌려준다. 세션·창 소유권과 전송 범위를 검사하고 중복·늦은 확인으로 한도가 늘지 않게 한다. 채널 전송 성공이나 `write()` 반환을 처리 완료로 쓰면 큐가 무한히 자랄 수 있다. 확인 대기는 그 세션의 읽기만 막고, 키 입력·크기 변경·종료는 별도로 계속 받는다. 탭/창을 닫거나 채널이 실패하면 대기 작업을 깨운다.
4. **자동 검증 — 출력 지연과 데이터 손실을 구분한다.** `cargo test --manifest-path src-tauri/Cargo.toml terminal` 및 F00의 Vitest 명령으로 1단계 시험을 다시 실행한다. 번호·마지막 표식, 한글 및 제어 시퀀스가 올바르게 반영된 터미널 버퍼, 중복 구독 수, 미확인 바이트 최고치와 닫기 완료를 비교한다. 이벤트 추적에는 세션별 순번·크기·처리 위치만 쓰고 셸 입력 원문이나 인증 자료를 기록하지 않는다. 두 OS에서는 `npm run tauri dev`로 실제 WebView를 열어 아래를 시행한다.

## 실기기 시연과 완료 증거

1. **T1 로컬 — OS마다 한 번씩.** 가운데 셸에서 영문 모드로 표식 `X`를 입력하고 Enter를 누르지 않는다. 두벌식으로 바꿔 물리 키로 `ㅎ → ㅏ → ㄴ`을 조합하고 공백 없이 Backspace를 누른다. `X한 → X하`를 눈으로 확인한다. `ㄴ`을 다시 넣고 공백으로 확정해 `X한 `이 보이는지 확인한다. Backspace 한 번이면 `X한`, 다시 누르면 `X`만 남아야 한다. `Ctrl+C`로 시험 줄을 비운다. `T1 Windows 로컬`, `T1 Linux 로컬` 각각 조합 중·확정 후·삭제 후를 기록한다. SSM 두 조합은 SSM 구현 티켓에서 같은 절차로 별도 판정한다.
2. **T2 입력·붙여넣기 — 아래 8칸마다 처음부터.** 일반 터미널 기준선과 같은 빈 시험 디렉터리로 이동한 뒤 앱의 가운데 탭에서 해당 CLI 하나만 실행한다. 입력창에 `한` 조합 중 Backspace로 `하`를 만든다. 식별 가능한 두 줄(예: `첫 줄`과 `둘째 줄`)을 한 번 붙여넣고 줄 수와 내용, 제출 전 응답이 없는지 본다. 끝에 `도구를 사용하지 말고 1부터 100까지 한 줄씩 적어 줘.`를 붙여 한 번 제출한다. 입력·응답은 외부 CLI 자체 화면에서 관찰한다.
3. **T2 취소·복원 — 같은 실행을 이어간다.** 응답을 받는 중 창 너비를 바꾸고 집중 보기를 왕복한 뒤 다른 탭을 다녀온다. 출력 진행, 커서·줄바꿈·입력 위치를 본다. 응답이 끝나기 전에 그 CLI가 안내한 취소 동작을 사용한다. 응답이 이미 끝났다면 같은 요청을 다시 보내 실제 진행 중 취소를 관찰한다. 같은 CLI에 `확인`을 보내 새 응답을 받은 뒤 안내된 종료 동작으로 CLI만 끝낸다. 복원된 셸에서 `echo TERMINAL_OK`를 직접 친다. 입력 에코가 정상이며 결과 줄 `TERMINAL_OK`가 정확히 한 줄이어야 한다. `--version`, 강제 탭 닫기 또는 다른 CLI의 결과로 이 단계를 대체할 수 없다.
4. **공통 부하 — OS별 별도 판정.** Linux에서 `yes`, Windows PowerShell에서 `while ($true) { Write-Output 'test' }`를 잠시 실행한 뒤 물리 키 `Ctrl+C`로 멈춘다. 같은 탭에서 `echo AFTER_LOAD`가 한 줄 출력되고 다른 탭도 응답하는지 본다. 입력이 멎으면 마지막 전송 위치와 마지막 처리 위치를 비교해 출력 밀림·채널 단절·자식 종료 중 어느 단계에서 멈췄는지 기록한다. 부하 시험은 T2 대화 시험 한 칸도 대신하지 않는다.
5. **기록과 완료:** 각 칸에 결과, OS·WebView·CLI 버전, 입력기와 Linux 세션 종류, 2~3단계 관찰 또는 최초 실패 지점, 시험용 녹화/캡처 위치를 적는다. 미설치·인증 불가·공급자 장애는 `미실행(사유)`, 정상 기준선에 비해 앱에서 동결·중복·복원 실패가 발생하면 `실패(단계)`다. 계정 식별자나 비밀은 증거에서 제외한다. T1 로컬 2건과 T2 8칸 모두의 실기기 통과 및 부하·자동 시험 결과를 첨부한다. WSL·브라우저·자동 합성 키는 실기기 증거를 대신할 수 없다. macOS는 장비 확보 후 별도 시행한다.

**T2 Shift+Enter — `omp`와 Claude Code만 별도 확인.** 각 OS의 실제 CLI 입력창에서 `첫 줄`의 IME 조합을 끝내고 Shift+Enter를 누른 뒤 `둘째 줄`을 입력한다. 모델에 전송되지 않고 입력창에 두 줄이 구분되어 남는지 확인한다. 최종 제출은 승인된 시험 계정에서 일반 Enter를 한 번 눌러 확인한다. 줄바꿈과 제출 결과를 각 도구의 T2 칸에 따로 기록한다.
