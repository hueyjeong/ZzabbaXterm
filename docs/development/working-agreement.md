# 구현 규칙: 한 티켓에서 한 동작을 끝낸다

경로 표기: `app/...`은 저장소 루트 기준이고, `src/...` 또는 `src-tauri/...`는 `app/` 기준이다. 개발 명령은 `app/`에서 실행한다. F00의 최초 생성 명령만 저장소 루트에서 실행한다.

## 기술 선택

**React + TypeScript + Vite를 사용하고 Next.js는 사용하지 않는다.** 이 제품의 화면은 검색 엔진이나 브라우저 클라이언트에 서버가 그려 보내는 페이지가 아니라 설치본에 들어가는 정적 자산이다. React는 탭·트리·마법사·채팅 상태와 키보드 포커스처럼 여러 화면 요소가 함께 변하는 부분에 쓴다. `vite`는 개발 서버와 프로덕션 자산 빌드를 맡고, 배포 시 별도 Node.js 서버는 없다. PTY·네트워크·파일 접근은 이미 Tauri/Rust가 담당한다. Next.js 정적 내보내기도 가능하지만 이 앱에서는 서버 렌더링이나 API 라우트를 쓸 곳이 없고 빌드 구성이 하나 더 생긴다. 터미널 자체는 xterm.js 인스턴스가 그린다. 터미널 출력을 React 상태에 한 줄씩 쌓지 않는다.

근거: [Tauri의 프런트엔드 선택](https://v2.tauri.app/start/frontend/), [Vite 설정](https://v2.tauri.app/start/frontend/vite/), [Next.js 정적 내보내기 조건](https://v2.tauri.app/start/frontend/nextjs/).

## 기능을 넣는 위치

제품 코드의 시작점은 F00에서 만들 `app/`이다. 아래 경로는 **각 기능이 처음 필요해질 때** 만든다. 이 단계에서 모든 폴더를 미리 만들 필요는 없다.

L01에서 Enter를 한 번 눌렀을 때를 따라가면 경계가 보인다. **xterm.js**가 키를 받고 **Tauri IPC**(화면과 Rust 프로세스 사이의 통신)로 전달한다. Rust는 해당 **PTY**(셸이 실제 터미널로 인식하는 입출력 장치)에 바이트를 쓴다. PowerShell/Bash가 실행해 낸 결과는 반대 방향으로 돌아와 같은 xterm.js 화면에 그려진다. 이 왕복이 첫 버티컬 슬라이스다. UI 전체나 Rust 백엔드 전체를 먼저 완성하는 방식과 다르다.

| 위치 | 여기에 두는 것 | 여기에 두지 않는 것 |
|---|---|---|
| `app/src/features/<기능>/` | 해당 티켓의 React 화면, 상태 전이, Tauri 호출과 화면 행동 테스트 | 운영체제 분기, SSH 키·암호, 터미널 출력 전체 사본 |
| `app/src-tauri/src/<기능>/` | 기능별 Rust 명령, 프로세스/파일/연결 소유권, 상태와 오류, 같은 모듈의 행동 테스트 | 프런트가 보낸 대상·명령을 검증 없이 실행하는 범용 핸들러 |
| `app/src-tauri/src/lib.rs` | 기능별 명령 등록과 장수 상태 초기화 | 모든 프로토콜 구현을 담는 거대 파일 |
| `app/src-tauri/capabilities/` | 로컬 앱 창에 필요한 Tauri 코어·플러그인 권한 | 원격 페이지의 IPC 허용, 포괄적인 시스템 셸·파일 접근 권한 |

**세션 계약:** `연결 ID`는 저장한 대상, `세션 ID`는 Rust가 발급한 한 번의 접속, `탭`은 표시 위치다. 같은 대상을 두 번 열어도 다른 세션이다. 활성 탭은 표시 상태일 뿐 입력 라우팅이나 AI 승인의 권한이 아니다. 열기·리사이즈·종료처럼 답이 한 번 오는 동작은 Tauri 명령으로, PTY 바이트처럼 계속 들어오는 데이터는 세션별 순서가 있는 채널로 전달한다. Rust는 호출 창·소유자·세션의 생존 여부를 함께 확인한다. 탭이나 창을 닫았을 때 자식 프로세스·채널·터널 정리를 끝내는 쪽도 Rust다. 작업 중 응답은 요청 당시 ID로 돌려준다.

**신뢰 경계:** Tauri WebView 명령은 설치본에 포함된 로컬 UI에만 연다. 별도 CLI는 로컬 소켓의 조회·초안·제안처럼 좁은 기능만 호출하고, 사용자 승인은 로컬 UI가 맡는다. 일반 셸의 사람 입력과 모델·CLI의 제안은 별개 진입점이다. 일반 셸 입력을 AI 도구로 노출하지 않는다. Rust는 요청별 권한과 실제 대상을 다시 검사한다. 창별 capability만으로 사용자 정의 명령이 자동 보호된다고 가정하지 않는다. 원격 출력·파일명·대화는 데이터로 렌더링하고, 승인·암호 프롬프트는 신뢰된 로컬 동작으로만 연다. 설정에는 연결 참조만 보존한다. 오류는 `대상 없음`, `권한 거부`, `단절`처럼 복구 행동을 정할 정도로 구별하고 원본 비밀은 전달하지 않는다.

근거: [Tauri 명령](https://v2.tauri.app/develop/calling-rust/), [스트림 채널](https://v2.tauri.app/develop/calling-frontend/), [capability와 앱 명령 권한](https://v2.tauri.app/security/capabilities/).

## BDD 한 바퀴: 한 문장부터 시연까지

1. **예를 고른다.** `Given`은 준비 상태, `When`은 한 번의 사용자 행동, `Then`은 화면이나 외부에서 관찰할 결과다. 예: **두 로컬 셸이 열려 있고 / 첫 탭을 닫으면 / 둘째 탭에서 `echo B_ALIVE`의 결과를 받는다.** 클릭 횟수나 내부 함수 호출 횟수는 인수 결과가 아니다.
2. **Red:** 티켓의 첫 시나리오 하나만 선택한다. UI 상태 전이는 기능 폴더의 `*.test.ts(x)`에서 Vitest, 파일·프로세스 소유권은 Rust의 `#[test]`로 검증한다. 위 예라면 독립 세션 둘을 열어 첫째를 닫고 둘째에서 다시 출력이 오는지 검증한다. 필터 실행 후 **예상 동작 때문에 실패한 검사 이름·관찰값**을 기록한다. 설치 오류나 테스트 0개는 Red가 아니다.
3. **Green:** 화면 조작에서 IPC, 실제 작업, 결과 표시까지 가장 얇은 한 경로를 잇는다. 그 테스트가 통과하면 취소·단절·동시 입력 중 티켓에 명시된 다음 예로 넘어간다. 테스트용 대체물로 UI의 오류 처리를 검사할 수 있지만 실제 PTY·AWS·IME의 합격 근거는 별도로 수집한다.
4. **시연:** `app/`에서 `npm run tauri dev`로 **실제 데스크톱 창**을 연다. 같은 행동을 수행하고 예상과 실제 결과를 대조한다. OS IME 조합, 창 버튼, 대화형 CLI, SSO, 그래픽 화면은 브라우저나 WSL 결과로 바꾸지 않는다. 물리 IME는 실제 한국어 두벌식에서 입력한다.

BDD에 별도 Gherkin/Cucumber 실행기를 요구하지 않는다. 시나리오는 티켓에서 읽고, 검사 이름에는 티켓 ID와 사용자 결과를 적는다. F00가 추가한 `npm test -- <파일>`(Vitest 단발 실행), `cargo test --manifest-path src-tauri/Cargo.toml <필터>` 중 해당 경로만 실행한다. 필터가 기대한 테스트를 실제로 선택했는지 건수도 본다. 위 명령의 기준 디렉터리는 `app/`이다.

## 티켓을 닫는 법

티켓을 구현한 PR 또는 팀의 이슈 본문에 아래 내용을 기록한다. 미실행일 때는 막힌 조건과 다시 실행할 절차를 함께 남긴다. 외부 계정·운영 명령·관리 노드 ID·금고 항목·토큰·원격 작업 내용은 공유 증거에서 가린다.

| 필드 | 남길 내용 |
|---|---|
| 실행 대상 | 티켓/시나리오 ID, 연결된 T번호(있을 때), 빌드 식별자, OS·셸·입력기·WebView·CLI 버전 중 관련 값 |
| 자동 판정 | 실행한 명령과 선택된 검사, 처음 실패한 이유 → 수정 후 결과. 자동화가 적합하지 않은 항목은 수동 재현 절차 |
| 네이티브 판정 | 준비 상태·행동·기대·실제값, `통과`/`실패`/`미실행(사유)`, 개인 정보 없는 화면·출력 또는 관찰 기록 |
| 정리 | 탭·앱 소유 세션·터널·임시 파일 정리 결과. 실패 시 보존할 편집 버퍼나 기존 설정에 미친 영향 |

한 티켓의 모든 필수 시나리오를 다시 따라 할 수 있고 실제 결과가 기대와 일치하면 완료다. 실패한 조합은 다른 OS·다른 서비스의 결과와 평균 내지 않는다. 첫 구현 작업은 [F00](00-start/01-bootstrap.md)이다.
