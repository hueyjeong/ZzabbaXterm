# R03 인증된 경로에서 Rust RFB 클라이언트로 VNC 열기

선행: R01

사용자 결과: 가운데 탭에서 VNC 서버의 화면을 보고 조작한다. 평문 RFB는 신원을 확인한 터널 안에서만 사용하고, VNC 서비스 인증은 터널 인증과 별도로 처리한다.

제목줄의 **VNC**는 이름·인증서를 검증하는 TLS 1.2 이상 직접 연결을 연다. 준비된 로컬 SSH 전달 행의 **VNC로 열기**는 고정 SSH 호스트의 승인된 루프백 VNC 서비스에만 연결한다. 서비스 인증은 경로와 별도로 처리하고 실패한 경로를 다른 경로로 바꾸지 않는다. 준비된 SSM 전달 행의 **VNC로 열기**는 노드 자신의 루프백 VNC 서비스에만 연결한다. T5 실서비스 인수는 별도다.

준비물: Windows 11·Ubuntu 24.04 GNOME Wayland, 승인된 비운영 VNC 서버, 서버와 같은 호스트에서 끝나는 R01 SSH 또는 SSM 터널, VNC 시험 계정 또는 비밀번호, 서버의 기능을 확인할 기준 VNC 뷰어. 직접 경로를 제공하려면 서버 신원을 검증할 수 있는 암호화 RFB 구성이 추가로 필요하다. 아래 명령은 구현 시점의 `app/` 기준이다.

## 인수 조건

- Given 인증된 터널과 허용된 VNC 인증 방식 / When 원격 편집기를 클릭하고 글자를 입력 / Then 그 서버가 보낸 변경 프레임에 입력 결과가 나타나고 다른 탭의 화면은 유지된다.
- Given 암호화 없는 직접 경로나 인증에 실패한 터널 / When 연결을 요청 / Then VNC 비밀 조회·전송 전에 중단한다. 로컬 주소라는 사실만으로 앱 소유 터널이라고 판단하면 실패다.
- Given 연결이 끊긴 화면 / When 다시 연결 / Then 경로와 인증을 새로 확인하고 첫 전체 프레임부터 다시 그린다. 이전 화면만 남거나 분리된 입력이 나중에 실행되면 실패다.

## 구현 순서

1. **Red.** `app/src-tauri/src/vnc/`에 경로별 비밀 접근 횟수, 잘못된 크기·픽셀 길이, 끊긴 ID의 입력 거부 테스트를 둔다. `app/src/features/vnc/`에서는 크기가 다른 canvas의 포인터 좌표 환산과 첫 전체 프레임 전에 도착한 예전 세션 이벤트 폐기를 Vitest로 고정한다.
2. **Green — 엔진 선택.** [vnc-rs의 `VncConnector` 예제](https://docs.rs/vnc-rs/latest/vnc/)를 출발점으로 Rust에서만 소켓과 RFB 인증을 연다. 고정할 버전에서 실제 서버와 보안 방식, 프레임, 키·포인터, 양방향 CutText, 해상도 변경 확장을 각각 대조한다. 빠진 메시지는 [RFB 명세](https://github.com/rfbproto/rfbproto)를 기준으로 해당 Rust 경로를 보완하거나 같은 조건을 만족하는 Rust RFB 엔진을 고른다. 기준 뷰어에서 되는 기능이 후보에 없으면 `클라이언트 미구현`이지 서버 미지원이 아니다. RDP 엔진이나 브라우저에 비밀번호를 넘기는 뷰어로 대체하지 않는다.
3. **Green — 신원과 화면.** R01의 소유 ID와 승인한 실제 서버·서비스 포트를 대조한다. 검증된 터널 밖 직접 연결은 원격 이름·인증서를 확인한 TLS 등 인증된 암호화 방식만 허용하고 평문 강등을 거부한다. 서비스 비밀은 확인한 대상의 참조에서만 해석해 Rust 인증 콜백에 전달한다. Rust가 발급한 세션 ID와 프레임 크기를 확인한 뒤 변경 사각형을 디코딩해 Tauri 바이너리 채널로 보낸다. `CopyRect`는 기존 화면의 영역 복사다. 탭 canvas는 순서대로 적용하고 새 연결에서는 전체 갱신을 요청한다.
4. **Green — 입력과 크기.** 포커스된 탭의 키 누름/뗌은 RFB 키 심볼로, 포인터는 원격 화면 좌표와 버튼 상태로 보낸다. 셸·채팅과 입력을 공유하지 않는다. 사용자가 복사한 시험 텍스트로 `ClientCutText`와 `ServerCutText` 양방향을 연결한다. 서버 크기 알림과 클라이언트의 `SetDesktopSize` 요청을 구분하고 서버가 돌려준 결과 크기로 판정한다. 연결 단절 시 해당 ID 입력을 닫고 재접속 때 이전 세션의 입력·프레임을 버린다.
5. **자동 검증.** `cargo test --manifest-path src-tauri/Cargo.toml vnc`와 `npx vitest run src/features/vnc`로 경로 거부·프레임 경계·입력 전달을 검증한다. 창 크기만 늘어나는 사례는 서버 해상도 변경 성공에서 제외한다.
6. **실기기 시연(T5 VNC).** 두 OS에서 원격 화면의 고유 문구, 키·클릭 결과, 양방향 클립보드의 서로 다른 시험 문구, 서버 해상도 전후를 관찰한다. 앱 소유 시험 터널을 끊고 다른 탭이 살아 있는 상태에서 재접속 후 새 문구를 입력한다. 클라이언트 OS·서버/엔진 버전·경로·협상 방식·항목별 결과와 비밀을 가린 화면을 남긴다. 기준 뷰어와 서버 설정/협상 결과로 확인된 미지원은 그 조합에만 적고 앱 결함은 `실패`, 장비 부재는 `미실행(사유)`으로 적는다. RDP/xrdp 결과는 VNC 완료 증거가 아니다.

## 저장 프로필로 열기

연결 트리의 VNC 프로필은 `app/src/features/remoteDesktop/desktopProfile.ts`의 `openDesktopProfile`로 연다. 직접 경로는 입력칸만 미리 채운다. SSH 경로는 저장된 직접 SSH 대상으로 서버 루프백 `-L` 전달을 승인받아 열고, Rust가 준비 완료로 확인한 전달을 탭의 터널 출처로 넘긴다. 평문 RFB는 SSH 서버 자신의 서비스에만 쓰므로 SSH·SSM 경로의 호스트는 비워 둔다. 연결은 사용자가 **직접 TLS 연결** 또는 **SSH 터널로 연결**을 눌러 시작한다. SSM 경로는 프로필 자신을 경로 대상으로 노드 자신의 서비스 포트에 공식 SSM 포트 전달(`AWS-StartPortForwardingSession`)을 승인받아 열고, Rust가 세션 소유권까지 확인한 전달을 같은 방식으로 넘긴다. Linux 금고의 `user` 범위는 `ssm://프로필@리전/노드|vnc://[127.0.0.1]:포트`다. 실제 AWS 경로는 미실행이다([R01 SSM 포트 전달](01-tunnels.md#ssm-포트-전달)).
