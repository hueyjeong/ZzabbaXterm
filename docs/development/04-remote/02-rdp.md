# R02 Windows RDP와 Linux xrdp를 같은 엔진으로 열기

선행: R01

사용자 결과: 가운데 탭에 실제 원격 데스크톱이 열리고, 키 입력과 클립보드가 선택한 데스크톱에만 전달된다. xrdp를 SSM 터널로 열어도 인증 대상은 원격 xrdp 서버다.

제목줄의 **RDP**는 직접 접속한다. 준비된 로컬 SSH 전달 행의 **RDP로 열기**는 Rust가 소유한 그 연결을 사용한다. 두 경로에서 원격 인증서 이름을 따로 확인하고 검증된 TLS 위에서 NLA/CredSSP NTLM을 사용한다. 서버가 NLA를 지원하지 않고 `PROTOCOL_SSL`(TLS 전용)만 고르는 경우에는 연결 설정의 **NLA를 지원하지 않는 서버(TLS 전용) 허용**을 켠 사용자만 같은 대상으로 한 번 재연결해 TLS 위 Client Info로 계정을 전달한다. 준비된 SSM 전달 행에서도 같은 방식으로 **RDP로 열기**를 사용한다. SSM 경로의 포워드 목적지는 노드 자신(루프백) 또는 TLS 인증 이름과 같은 원격 호스트만 받는다. TLS 인증 이름은 DNS 이름 또는 표준 표기의 IP 주소(`10.0.1.25`, `2001:db8::25`)다. IP 주소는 인증서의 IP SAN으로 확인하고, 리졸버가 IP로 해석하는 숫자 꼬리 이름(`2852039166`, `127.1`)은 받지 않는다.

준비물: 네이티브 Windows 11·Ubuntu 24.04 GNOME Wayland 클라이언트, 승인된 비운영 Windows RDP 및 Linux xrdp 서버, 검증 가능한 원격 DNS 이름 또는 IP SAN과 신뢰 CA, 시험용 원격 계정·필요한 경우 도메인, xrdp 관리 노드의 SSM 전달 권한. 정상 원격 접속 도구와 같은 계정으로 서비스·정책을 먼저 확인한다. 아래 명령은 구현 시점의 `app/` 기준이다.

## 인수 조건

- Given Windows RDP 또는 Linux xrdp / When 탭을 열고 원격 편집기에 시험 문구를 입력 / Then 서버가 보낸 프레임에 그 문구가 나타난다. xrdp 직접과 SSM 경유 모두 같은 원격 이름을 검증한다.
- Given TCP 상대가 루프백인 터널 / When 서버 인증서의 이름·유효기간·체인 중 하나가 틀림 / Then 승인 카드의 `사유`에 이름 불일치·만료·알 수 없는 CA를 표시하고, 승인하지 않으면 자격 증명을 전송하기 전에 중단한다. 승인한 뒤에는 저장한 지문 일치가 연결 조건이다.
- Given 다른 탭이 열린 상태 / When 사용 중인 시험 터널을 종료하고 다시 연결 / Then 해당 탭만 끊기고 재접속 후 새 원격 프레임과 입력을 확인할 수 있다. 예전 세션의 입력은 재전송되지 않는다.
- Given NLA를 지원하지 않는 xrdp / When opt-in을 켜고 연결 / Then 첫 NLA 협상이 `SSL`을 받으면 연결을 닫고 같은 대상·같은 인증서 검증으로 TLS 전용 한 번만 재연결하며, 승인 카드와 연결 상태에 `TLS 전용(표준 RDP 보안 없음)`이 표시된다. opt-in이 꺼져 있으면 자격 증명을 보내지 않고 opt-in 이름을 포함한 오류로 끝난다.
- Given TLS 전용 연결 / When 인증서 이름·체인·유효기간 중 하나가 틀림 / Then 사유를 승인 카드에 표시하고, 승인하지 않으면 Client Info를 보내기 전에 중단한다. 승인 후에는 지문 일치가 연결 조건이다.

## TLS 전용 모드

- **정책**: 기본은 NLA 우선이다. 첫 연결은 `enable_credssp=true, enable_tls=false`로 `HYBRID|HYBRID_EX`만 요청하므로 서버가 TLS로 다운그레이드할 수 없다. 서버가 `SSL`을 고르면 연결을 닫고, opt-in이 켜진 경우에만 `enable_credssp=false, enable_tls=true`로 같은 대상에 한 번 재연결한다. 재시도는 한 번뿐이며 opt-in은 기본 꺼짐이다.
- **자격 증명**: TLS 전용에는 CredSSP가 없으므로 사용자·도메인·비밀번호는 검증된 TLS 위의 Client Info PDU로 전달한다. 승인 카드·금고 경로는 NLA와 같고, 비밀번호를 로그·argv·WebView에 남기지 않는다. 세션 활성화 후 `ConnectTimeAutoDetection`에서 config의 자격 증명을 비운다.
- **인증서**: TLS 전용도 원격 이름(DNS 이름 또는 IP 주소)·체인·유효기간을 검증한다. 인증서 검증을 끄는 옵션은 없다. 자체 서명 서버는 시험용 CA를 OS 현재 사용자 신뢰 저장소에 설치해 검증하고, 사용이 끝나면 제거한다.
- **표시**: opt-in을 켜면 승인 카드와 연결 상태에 `NLA, 미지원 시 TLS 전용(표준 RDP 보안 없음)`을 표시한다. opt-in이 꺼진 채 서버가 `SSL`을 고르면 `RDP 서버가 NLA를 지원하지 않습니다. 연결 설정에서 'NLA를 지원하지 않는 서버(TLS 전용) 허용'을 켜야 합니다`로 중단한다.

## 구현 순서

1. **Red.** `app/src-tauri/src/rdp/`에 시험 CA로 발급한 이름 일치·불일치·만료 인증서와 다른 CA 사례를 넣고, 검증 실패 후 인증 단계 호출이 0인지 검사한다. `app/src/features/rdp/`에는 실제 프레임 수신 전 연결 표시, 폐기한 세션의 프레임, 비활성 탭 입력 억제를 Vitest 사례로 둔다.
2. **Green — 접속.** [IronRDP](https://github.com/Devolutions/IronRDP)의 네이티브 클라이언트 예제를 따라 `connector`·`session`·그래픽 디코더를 Rust에서 구동한다. TCP 주소(직접 또는 R01 루프백)와 TLS 검증용 원격 서버 이름을 별도 필드로 둔다. OS 신뢰 저장소 또는 승인된 시험 CA로 검증한 뒤 대상이 요구한 TLS/NLA 협상을 완료한다. 서비스용 계정·도메인과 사용자가 선택한 비밀 참조는 로컬 인증 컴포넌트에서만 해석한다. 인증서 전부 허용, 비밀번호 인자, WebView로의 금고 값 반환은 제외한다. 정상 서버가 요구하는 협상을 지원하지 못하면 협상 단계를 기록하고 구현 결함으로 남긴다.
3. **Green — 화면과 입력.** Rust가 발급한 세션 ID별로 프레임을 디코딩해 크기·변경 사각형·픽셀 바이트를 Tauri 채널로 보내고 탭의 canvas에 그린다. Rust에서 사각형과 길이를 확인한다. 포커스된 canvas의 키 누름/뗌과 포인터를 원격 좌표·RDP 입력 이벤트로 변환한다. 셸 PTY나 AI 입력을 경유하지 않는다. 탭 폐기 시 입력 핸들·터널 소유권을 함께 해제한다.
4. **Green — 주변 기능.** 협상한 CLIPRDR에서만 사용자가 복사한 시험 텍스트의 형식과 본문을 양방향 교환한다. Display Control 채널로 크기 변경을 요청하고 서버가 보낸 새 화면 크기로 canvas를 갱신한다. CSS 확대는 해상도 변경이 아니다. 단절 시 입력을 잠그고 재접속에서 경로와 인증서를 다시 검증해 새 ID의 프레임만 그린다.
5. **자동 검증.** `cargo test --manifest-path src-tauri/Cargo.toml rdp`와 `npx vitest run src/features/rdp`에서 신원·프레임·입력 경계를 검증한다. 조작한 인증서로도 첫 인증 단계에 진입하면 수정 후 재시험한다.
6. **실기기 시연(T5 RDP).** 각 클라이언트에서 `Windows RDP 직접`, `Linux xrdp 직접`, `Linux xrdp / SSM`을 별도 행으로 기록한다. 첫 프레임 → 키·클릭 → 서로 다른 무해한 문자열의 양방향 복사 → 서버 해상도 변경 전후 → 끊기·재접속 후 새 문자열 입력을 촬영한다. SSM을 끊는 동안 별도 탭의 입력도 기록한다. OS·서버·IronRDP 버전과 협상 채널을 붙인다. 서버 정책/협상과 기준 클라이언트에서 모두 막힌 기능만 해당 행의 `서버 미지원(근거)`이다. 앱에서만 실패하면 `실패(단계)`, 시험 환경이 없으면 `미실행(사유)`이다. 계정 비밀과 클립보드 원문은 로그에 넣지 않는다.

## 인증서 신뢰와 지문 고정

- **판정 순서**: 서버 인증서가 OS/CA 체인으로 검증되고 원격 이름이 맞으면 승인 창 없이 진행한다. 체인 또는 이름 검증이 실패하면(자체 서명 xrdp, IP SAN이 없는 인증서 등) 네이티브 승인 창에 원격 이름, 대상 `host:port`, 주체, SAN(DNS 이름과 IP 주소), SHA-256 지문을 보여 주고 1회 승인을 받는다.
- **저장**: 승인한 지문은 `${appData}/rdp-trust.json`에 `(원격 이름, 대상 host:port) → { fingerprint, approved_at }`으로 원자적 쓰기한다. SSH·SSM 전달 경로는 대상이 루프백이라 경로끼리 같을 수 있으므로 키에 경로 대상 ID를 더한다. 읽을 때는 새 키가 없으면 경로 대상 ID가 없는 예전 키와 IPv6를 괄호 없이 적은 예전 키(`::1:3389`)도 찾는다. 저장은 새 키로만 한다. 손상된 JSON은 빈 상태로 시작하며 조용히 신뢰하지 않는다.
- **변경**: 지문이 저장값과 다르면 연결을 중단하고 네이티브 승인 창에 **"RDP 서버 인증서가 바뀌었습니다"**, 이전 지문과 새 지문, 사유를 나란히 보여 주며 **"새 지문으로 교체하고 연결합니까?"**로 묻는다. 이 창은 취소가 기본 버튼이다. 승인 전에는 자격 증명을 보내지 않고, 거부하면 저장된 지문은 그대로 둔다. 자동 갱신은 없다.
- **체인 실패 후의 범위**: 체인 검증이 실패해 1회 승인한 뒤에는 그 지문만 검증한다. 이름 불일치·만료·알 수 없는 CA 같은 체인/이름/유효기간 문제는 승인 카드의 `사유` 항목으로 표시하며, 승인 후에는 지문 일치가 연결 조건이다.
- **범위**: TLS 전용(opt-in)과 NLA 경로 모두 같은 규칙을 쓴다. 인증서 검증을 끄는 옵션은 없다. 2026-11-23 실측 시점에 이 Windows 사용자 신뢰 저장소에는 시험 CA가 남아 있지 않다(`certutil -user -store Root`에서 0건).

## 입력 전달과 승인 창

- **입력 큐**: 탭은 입력을 최대 512개까지 쌓고 키·포인터·활성·해제를 `rdp_input_batch`로 64개씩 묶어 보낸다. 복사·붙여넣기·해상도 변경은 묶지 않고 `rdp_input`으로 하나씩 보낸다. 큐가 넘치면 버튼 상태가 같은 오래된 포인터 이동부터 버리되 큐의 마지막 포인터는 남기고, 연결은 끊지 않는다. 키 입력까지 버리면 `RDP 입력 일부를 버렸습니다`를 표시하고 큐가 빈 뒤 `release`를 한 번 보내 눌린 키를 해제한다.
- **결과와 순번**: `rdp_input`·`rdp_input_batch`의 항목 결과는 `ok`·`stale`·`busy`(묶음에서는 오류 `{ error, kind? }`도 포함)다. Rust는 세션 작업 큐에 최대 500ms 기다려 넣고, 그래도 차 있으면 `busy`로 답하며 그 순번을 쓰지 않는다. 묶음은 16개마다 입력 잠금을 놓는다. 탭은 순번을 `busy`가 아닌 결과에서만 올리고, `busy` 항목은 15ms 뒤 같은 순번으로 다시 보낸다. 같은 키·포인터 항목이 3초 넘게 `busy`면 그 항목과 같은 epoch의 남은 입력을 모두 버리고 바로 다음 순번으로 `release`를 보낸다(수정키 keyup만 빠져 뒤 키가 단축키로 적용되는 것을 막는다). 활성 전환이 3초 넘게 `busy`면 `RDP 세션이 입력 활성화를 받지 않아 연결을 닫았습니다`로 끝내고, `release`는 상한 없이 다시 보낸다. 복사·붙여넣기·해상도 변경은 `busy`여도 다시 보내지 않고 `RDP 세션이 작업 중입니다`를 표시한다. 앞선 복사 응답을 기다리는 중의 복사는 `busy`가 아닌 `RDP 복사가 진행 중입니다` 오류로 답해 뒤 입력을 막지 않는다. 탭에 보낼 채널·클립보드 이벤트가 밀려 복사를 시작할 수 없을 때는 `busy`다.
- **종료 종류**: `rdp_connect`와 입력 실패는 `{ kind?, message }`로 답한다. `kind: "transport"`는 전송 연결이 끊긴 종료이며, 터널 경로 탭은 이 값으로 경로를 다시 열지 정한다.
- **한글·유니코드 입력**: 키보드 포커스는 canvas가 아니라 화면 왼쪽 위의 숨은 `textarea`(`.remote-desktop-keyboard`)에 둔다. IME가 처리하는 keydown(`isComposing`, `key === "Process"`, `keyCode === 229`)은 스캔코드로 보내지 않고 기본 동작도 막지 않는다. 조합이 끝난 글자는 `compositionend`에서, 조합 밖에서 들어온 글자(이모지 패널, 자동화의 `insertText`)는 네이티브 `beforeinput`의 `insertText`에서 코드 포인트 단위로 `{ kind: "unicode", text }` 입력이 된다. Rust는 글자 하나를 `TS_UNICODE_KEYBOARD_EVENT` 누름·뗌으로 한 fast-path PDU에 담는다. BMP 밖 글자는 상위·하위 서러게이트를 차례로 누르고 같은 순서로 뗀다(IronRDP `ironrdp-input`과 같은 순서). 제어 문자는 버린다. 유니코드 입력도 같은 큐·순번·busy 재전송·묶음 규칙을 따르고 눌린 상태를 남기지 않는다. 스캔코드로 보낸 키는 keydown에서 기본 동작을 막으므로 입력칸 글자로 다시 들어오지 않는다. IME가 조합을 끝내며 넘긴 Enter(`insertLineBreak`)는 Enter 스캔코드 누름·뗌으로 한 번 보낸다. 조합 중에는 입력칸이 보이며 조합 글자를 표시한다. 단축키(Ctrl+C, Ctrl+V, Alt+Tab 등)와 특수 키는 그대로 스캔코드다. Chromium(WebView2)은 조합 이벤트 중 `compositionend`만 `isTrusted=false`로 보내므로, 신뢰 `compositionstart`로 시작한 조합만 받고 확정 글자는 `compositionend`가 신뢰 이벤트이면 그 값, 아니면 `compositionend`의 글자가 직전 신뢰 `compositionupdate`의 글자(확정 때 확정 글자로 한 번 더 온다)와 같고 비어 있지 않을 때만 쓴다. 취소한 조합(빈 글자)과 스크립트가 다른 글자로 앞당겨 만든 확정은 보내지 않는다. 조합 중 원격 화면을 클릭하면 입력칸을 blur해 조합을 확정하므로 확정 글자가 클릭보다 먼저 원격에 간다. 포커스는 다음 작업(`setTimeout(0)`)에서 돌려준다. 바로 돌리면 TSF IME가 조합 끝을 다 처리하기 전에 입력칸이 다시 조합을 받아 글자가 두 번 들어갈 수 있다. 포커스를 돌려주기 전의 포인터 이동과 뗌은 같은 클릭으로 보낸다. 창이 포커스를 잃을 때도 같은 방식으로 조합 중인 글자를 한 번 확정해 보낸 뒤 눌린 키를 해제한다. 연결 중이거나 첫 화면 전에 화면을 눌러도 포커스는 입력칸으로 옮기고, 키 전송은 화면이 준비될 때까지 막는다. 제목줄 단추를 눌러도 입력칸 포커스를 빼앗지 않는다(`TitleBar`의 `keepFocus`). 입력칸은 `wrap="off"`이고 확정 글자가 256자를 넘게 쌓이면 조합이 끝날 때 바로 비운다.
- **포커스 테두리**: 연결된 화면의 입력칸에 포커스가 있으면 canvas에 `data-keyboard="focused"`를 두고 초록 테두리를 그린다. 마우스로 눌러 포커스를 옮겨도 보이는 것이 의도한 동작이며, 키보드 입력이 원격으로 간다는 표시다.
- **알려진 한계(입력)**: 데드 키(US-International의 `'`·`` ` `` 조합 등)는 IME 조합이 아니라 물리 키 스캔코드로 보내므로 로컬이 아니라 원격 키보드 배열이 조합한다. 로컬 데드 키 조합 결과를 그대로 보내지는 않는다.
- **계정 창**: Windows는 앱이 메모리 대화 상자 템플릿으로 만든 계정 창(`rdp/account_dialog.rs`)을 쓴다. 이전의 `CredUIPromptForCredentialsW`는 계정 칸 목록에 Windows 자격 증명 관리자의 다른 항목 이름(토큰 이름, 이메일 등)을 보였다(R3). `CredUIPromptForWindowsCredentialsW`는 목록이 없지만 `CredentialUIBroker.exe` 창이라 UI 자동화로 시험할 수 없어 쓰지 않는다. Linux는 GTK 창이다. 두 창 모두 앱 프로세스의 네이티브 창이라 비밀번호가 WebView를 거치지 않고, 비밀번호를 저장하지 않으며, 확인 뒤 비밀번호 칸을 비운다. 세션이 열린 뒤 로그인한 계정 이름(`도메인\계정`)만 `${appConfig}/rdp-accounts.json`에 인증서 고정과 같은 대상 키(원격 이름, 대상 `host:port`, 전달 경로 대상 ID)로 저장하고, 다음 연결의 계정 칸에 미리 채운 뒤 비밀번호 칸에 포커스를 둔다. 손상된 파일은 기억한 계정이 없는 것으로 보고, 저장 실패는 연결을 막지 않는다. 읽기와 쓰기는 `spawn_blocking`에서 하고, 쓰기는 프로세스 안에서 직렬화하며, Unix에서는 파일을 `0o600`으로 만든다. TLS 전용 연결은 Client Info로 계정을 보내므로 계정이 틀려도 세션이 열리면 그 이름을 저장한다.
  - **계정 창 입력**: 계정과 비밀번호 칸이 모두 차야 로그인 단추가 켜진다. 계정이 `계정` 또는 `도메인\계정` 형식이 아니면 창을 닫지 않고 `계정 형식이 올바르지 않습니다`를 표시한다. 긴 대상 이름은 끝을 줄임표로 줄인다(`SS_ENDELLIPSIS`, GTK `EllipsizeMode::End`).
  - **연결 삭제**: 연결 대상이나 그룹을 지우면 지운 대상 ID를 전달 경로로 쓰던 키를 지운다. SSM 경로 프로필은 자기 ID가 경로 대상이라 함께 지워진다. 직접 연결 키(원격 이름과 `host:port`)는 저장 프로필 없이 연 탭과 같은 프로필끼리 함께 쓰므로 지우지 않고, SSH 경로 키는 경로로 쓰는 SSH 세션을 지울 때 지운다.
  - **알려진 한계(비밀번호 사본)**: Windows 계정 창의 비밀번호 입력칸은 Win32 EDIT 컨트롤이라 확인 뒤 칸을 비워도 컨트롤 내부 버퍼나 해제된 힙에 사본이 남을 수 있다. GTK `Entry`의 문자열과 IronRDP `connector::Credentials`가 갖는 비밀번호 사본도 앱이 지울 수 없다. 앱이 직접 잡는 버퍼(`Zeroizing`)만 지운다.
- **승인 창**: 연결 승인·계정·인증서 창을 띄우기 직전에 주 창의 최소화를 푼다. 앱이 이미 전경일 때만 포커스를 옮기고(Windows는 `SetForegroundWindow`를 직접 부르고 실패는 무시한다. tao `set_focus`는 실패 시 Alt 입력을 우회해 넣는다), 백그라운드면 포커스를 받을 때까지 작업 표시줄을 깜빡인다(`UserAttentionType::Critical`). Windows 연결 승인은 `MessageBoxW`(`MB_OKCANCEL | MB_ICONQUESTION | MB_SETFOREGROUND | MB_DEFBUTTON2`)를 쓴다. 창이 열려 있는 동안 출력 채널로 `approval`을, 닫히면 `approval-done`을 보내 탭에 `승인 창 확인 필요`를 표시한다. 창을 띄우지 못해도 `approval-done`은 가며, 이 신호는 승인 대기 알림만 지운다. 이 처리는 `app/src-tauri/src/desktop_dialog.rs`에서 VNC와 함께 쓴다.

## 화면 크기와 갱신 속도

- **첫 연결 크기**: 탭의 원격 화면 영역(`.remote-desktop-screen`)을 CSS 픽셀로 재고 `devicePixelRatio`를 곱한 장치 픽셀 크기와 배율(%)로 연결한다(`remoteDesktop/fit.ts`의 `fitSize`). 원격 화면이 1:1로 그려져 글자가 축소되지 않는다. 크기는 Display Control 범위(한 변 200 이상, 짝수 폭)와 프레임 한도(한 변 4096, 3840×2160 화소) 안으로 줄인다. 배율 100~500%만 서버에 알리며 xrdp는 배율을 쓰지 않는다. 영역이 0이거나 1초 안에 크기를 받지 못하면 1024×768로 연결한다. Rust `rdp_connect`는 초안의 `size: { width, height, scale }`를 같은 범위로 다시 검사한다.
- **창에 맞춤**: 기본으로 켜져 있다. 화면 영역이 바뀌면 400ms 동안 더 바뀌지 않을 때 그 크기와 배율을 Display Control로 요청한다. 같은 크기·배율은 다시 요청하지 않으므로 서버가 다른 크기를 적용해도 요청이 되풀이되지 않는다. 재활성화 중이거나 첫 화면 전이라 보내지 못한 요청(`Connection.resize`의 결과 `retry`)은 400ms 뒤 다시 요청한다. 창을 배율이 다른 모니터로 옮기면 `matchMedia(resolution)` 변화로 다시 잰다. 알림과 오류는 화면 영역 위에 겹쳐 띄워 영역 높이를 바꾸지 않는다. 서버가 Display Control을 열지 않으면 현재 크기를 유지하고 canvas를 영역에 맞춰 축소한다(`max-width`·`max-height: 100%`).
- **고정 크기**: **창에 맞춤**을 끄면 너비·높이 칸과 **해상도 변경**이 활성화된다. 칸은 현재 원격 크기로 채운다. 요청 5초 뒤에도 원격 크기가 그대로면 `서버가 해상도를 바꾸지 않았습니다`를 표시한다. 서버가 알린 최대 면적을 넘으면 `서버가 허용하는 최대 화면 면적을 넘습니다`로 답한다. 선택은 탭 단위이며 프로필에 저장하지 않는다. 다시 연결하면 고정 크기는 직전 원격 크기(폭은 짝수로 내리고 각 변 200 이상)로, 창에 맞춤은 다시 잰 크기로 연결한다.
- **Display Control 능력**: IronRDP 0.8의 `DisplayControlClient`는 능력 PDU 앞의 머리글(종류·길이 8바이트)을 건너뛰지 않고 읽는다. xrdp 0.9.24가 보낸 `MaxNumMonitors=16, FactorA=4096, FactorB=2048`이 5×20×16=1600화소로 계산되어 모든 해상도 변경이 `RDP 화면 또는 입력 범위가 올바르지 않습니다`로 거부됐다(R6b). `rdp/display.rs`의 `DisplayControl`이 머리글부터 읽어 서버가 알린 최대 면적(16×4096×2048)을 쓰고, 요청은 `DisplayControlMonitorLayout`을 직접 만들어 보낸다.
- **xrdp 재활성화**: R6b는 세 겹이었다. (1) 위 능력 해석 오류. (2) xrdp `libxrdp_reset`은 Client Core Data의 `clientBuild`가 419 이하이면 Deactivate All 없이 서버 화면만 새 크기로 바꾼다. 앱은 `clientBuild`를 0으로 보내고 있었으므로 19045(Windows 10 22H2)로 알린다. (3) xrdp의 Deactivate All은 ShareControlHeader 6바이트뿐이라 IronRDP가 `shareId`를 읽다 실패한다(`RDP 응답 형식 오류`). I/O 채널에서 온 것만 `frame::Normalizer`와 재활성화 순서가 `shareId` 0과 1바이트 `sourceDescriptor`를 붙인 PDU로 바꾼다.
- **재활성화 전 갱신**: xrdp는 Deactivate All보다 먼저 새 크기 좌표의 비트맵을 보낸다. 형식은 맞지만 현재 화면 밖을 가리키는 화면 갱신은 `Error::OutOfImage`로 다른 범위 오류와 나눈다. 해상도 변경을 보낸 뒤 재활성화가 끝날 때까지(최대 10초, `display::Resizing`) 끝 좌표가 요청한 크기 안인 갱신만 그리지 않고 버린다. 요청 크기 밖 좌표, 길이·형식 오류, 클립보드·DVC 채널 오류는 그대로 세션을 끝낸다. Deactivate All 뒤 재활성화가 끝날 때까지 오는 화면 갱신(fast-path와 slow-path Update·Pointer)은 재활성화 순서에 넘기지 않고 버린다(`connect::reactivation_step`). 재활성화가 끝나면 서버가 새 크기의 전체 화면을 다시 보낸다.
- **화면 갱신 합치기**: 세션 작업은 탭이 이벤트를 받을 수 있을 때만 프레임을 만들고, 탭이 앞 프레임을 받는 동안에는 서버를 계속 읽어 바뀐 영역을 하나의 사각형으로 합친다. 서버 연결이 끊기거나 서버가 세션을 끝내도(Terminate) 이미 받은 화면을 넘긴 뒤 끝낸다. 입력 명령은 서버 읽기보다 먼저 처리한다.

## 실측 기록

- xrdp 0.9.24(Ubuntu 24.04 패키지, `security_layer=negotiate`)는 `HYBRID|HYBRID_EX`만 요청하면 `RDP_NEG_RSP selectedProtocol = 0x0`(RDP 표준 보안)을 돌려주고, `SSL`을 요청하면 `0x1`(TLS 전용)을 돌려준다. 즉 NLA를 모르는 서버는 SSL로 다운그레이드하지 않고 RDP 표준 보안을 고른다. 앱은 NLA가 아닌 선택을 모두 NLA 미지원으로 보고 opt-in이 켜진 경우에만 `SSL` 요청으로 한 번 재협상한다.
- 시험 컨테이너 `zzabba-demo-remote`(xrdp 0.9.24, SSH `127.0.0.1:2299`)에 `SAN=DNS:xrdp.demo.test,DNS:localhost`인 시험 CA 서명 인증서를 설치하고, 그 CA를 Windows 현재 사용자 신뢰 저장소에 넣은 뒤 `localhost:13389`(SSH 로컬 전달 → 컨테이너 `127.0.0.1:3389`)로 앱에서 연결했다. 승인 카드와 연결 상태에 `NLA, 미지원 시 TLS 전용(표준 RDP 보안 없음)`이 표시됐고, xrdp 로그에 `requested [HYBRID|HYBRID_EX|RDP], selected [RDP]` 뒤 `requested [SSL|RDP], selected [SSL]`, `TLSv1.3`, Client Info 수신과 capability 교환이 기록됐다. 인증서 이름 불일치는 자격 증명 입력 전에 중단된다. (옛 이름 ZzabbaXterm 시절 측정)
- 압축 비트맵의 행 밀림(shear) 원인: xrdp가 RLE/RDP6 스트림을 원본 폭 8px로 보내는데 목적지 rect는 7px다. IronRDP는 원본 폭으로 디코드한 버퍼를 **rect 폭 7px stride로 적용**해 행마다 1px씩 밀렸다. `frame::Normalizer`가 원본 폭으로 디코드한 뒤 각 행을 목적지 폭으로 잘라 내고, 결과가 fast-path 15비트 길이(32,767)를 넘으면 행 밴드로 나눠 여러 PDU로 보낸다. 원본 선언 폭·높이는 디코드 전에 `frame_len`·rect 경계·데이터 길이로 검사한다. 같은 PDU의 포인터 등 다른 업데이트는 보존하고, 압축 비트맵 프래그먼트(First/Next/Last)는 재조립 후 정규화한다. `check_bitmaps`의 압축 폭 일치 검사는 복원했다.
- 자동 로그온: TLS 전용에서 `config.autologon=true`를 켜 Client Info에 `INFO_AUTOLOGON`을 실었다. xrdp가 sesman 로그인 창을 띄우지 않고 바로 세션을 시작한다.
- 컨테이너 세션 설정: `xrdp.ini`의 `[Xorg]`가 `port=tcp://127.0.0.1:3389`(자기 자신)로 잘못 잡혀 있어 `port=-1`로 고쳤고, `/etc/xrdp/startwm.sh`가 `twm`과 `xterm`을 띄우도록 바꿨다.
- 키 입력: IME가 처리하지 않는 키는 물리 키(`KeyboardEvent.code`) 기준 스캔코드와 수식 키 동기화를 쓴다. 자동화·IME가 Shift keydown 없이 `shiftKey=true`만 보내거나 Shift 해제를 잃어도 `input.ts`의 `modifierEvents`가 서버의 Shift/Ctrl/Alt/Meta 상태를 먼저 맞추고, blur 시 눌린 수식 키를 모두 해제한다. 클라이언트 키보드 레이아웃은 US(0x0409)로 알린다. 이 값은 xrdp가 `km-00000409.ini`를 선택하게 하는 근거이며, US가 아닌 물리 배열(예: 한글 두벌식 하드웨어)에서의 문자 매핑은 실기기 확인 항목으로 남긴다.
- 한글 입력 실측(2026-11-25, 개발 빌드, CDP `Input.imeSetComposition`·`Input.insertText`로 조합과 확정을 흉내 냄): xrdp 0.9.24(Ubuntu 24.04 패키지)와 0.10.1(Ubuntu 26.04 소스)은 `TS_UNICODE_KEYBOARD_EVENT`를 keymap에 있는 글자로만 바꾸고 나머지는 버린다(`xrdp_wm_key_unicode`). `echo X<조합 한글>< 테스트 123>X`가 `X 123X`로 도착했다(서버 미지원). xrdp devel(2026-11-20 `7a7a112`, `--enable-ibus`, xorgxrdp devel, 세션에서 `ibus-daemon` 실행)은 `Chansrv is handling Unicode input`을 기록하고 같은 입력이 `X한글 테스트 123X`로 그대로 도착했다. 조합 중 클릭은 `X하Y`로 확정 글자가 클릭 위치 앞에 남았다. 같은 세션에서 Ctrl+A·Ctrl+C·Alt+Tab은 스캔코드로 동작했고, Ctrl+V(bash quoted-insert)는 xrdp 0.9.24에서 동작했다. Windows RDP 서버는 시험하지 못했다.
- 계정 기억 실측: 첫 연결에서 계정 창에 `demo`와 비밀번호를 넣어 연결한 뒤 `rdp-accounts.json`에 `{"localhost\nlocalhost:13389":"demo"}`만 저장됐다. 다시 연결과 앱 재시작 뒤 연결에서 계정 칸에 `demo`가 채워지고 비밀번호 칸에 포커스가 있었다. 다른 대상(`localhost:23390`)의 첫 연결은 빈 계정 칸으로 시작했다.
- 최종 실측: `localhost:13389`(SSH 전달)로 연결해 지문 1회 승인 후 **로그인 창 없이 1024×768 데스크톱과 xterm이 표시**됐다. 실제 키 이벤트로 `echo XRDP_OK`를 입력해 `XRDP_OK`가 정확히 출력되고, `echo a-B_c:D`가 `a-B_c:D`로 출력되는 것을 확인했다. 스크린샷: 지문 승인 창 `C:\Users\deus\AppData\Local\Temp\omp-computer-15d902b0d2079de9.png`, 재연결 데스크톱 `C:\Users\deus\AppData\Local\Temp\omp-computer-15d906383a879dfc.png`, `XRDP_OK` `C:\Users\deus\orca\workspaces\ZzabbaXterm\rdp-tls\.omc\demo-remote\cdp-xrdp-ok2.png`, `a-B_c:D` `C:\Users\deus\orca\workspaces\ZzabbaXterm\rdp-tls\.omc\demo-remote\cdp-xrdp-ok.png`. 재연결에서는 지문 승인 창이 뜨지 않고 연결 승인·계정 창만 나타났다. - 확인 방법: 컨테이너의 `127.0.0.1:3389`에 X.224 `Connection Request` + `RDP_NEG_REQ`(`requestedProtocols`를 0x0b, 0x0a, 0x08, 0x02, 0x01로 각각)를 보내고 응답의 `selectedProtocol`을 읽는다. 0x0b·0x01은 0x1, 0x0a·0x08·0x02는 0x0이었다.

## 저장 프로필로 열기

연결 트리의 RDP 프로필은 `app/src/features/remoteDesktop/desktopProfile.ts`의 `openDesktopProfile`로 연다. 직접 경로는 프로필의 주소로 바로 연결한다. SSH 경로는 저장된 직접 SSH 대상으로 서버 루프백 `-L` 전달을 승인받아 열고, Rust가 준비 완료로 확인한 전달을 탭의 터널 출처로 넘긴다. TLS 인증 이름과 TLS 전용 허용 값은 프로필에서 채운다. 프로필로 연 탭은 경로가 준비된 뒤 입력칸 없이 한 번 바로 연결을 시작한다. 신뢰 경계는 Rust의 네이티브 연결 승인·계정·인증서 창이며, 빈 **RDP 연결** 메뉴로 연 탭만 입력칸을 보이고 사용자가 **직접 연결** 또는 **터널 연결**을 눌러 시작한다. 연결이 끊기면 오류와 **다시 연결**을 보이고, 입력칸은 **연결 설정 편집**을 눌렀을 때만 보인다. 터널 경로가 `kind: "transport"`로 끊기면 **다시 연결**이 같은 프로필의 경로를 다시 열고 새 경로로 연결한다. SSM 경로는 프로필 자신을 경로 대상으로 공식 SSM 포트 전달(`AWS-StartPortForwardingSessionToRemoteHost`, 원격 호스트는 프로필의 TLS 인증 이름)을 승인받아 열고, Rust가 세션 소유권까지 확인한 전달을 같은 방식으로 넘긴다. 승인 창에는 SSM 프로필·리전·관리 노드를 표시한다. 실제 AWS 경로는 미실행이다([R01 SSM 포트 전달](01-tunnels.md#ssm-포트-전달)).
